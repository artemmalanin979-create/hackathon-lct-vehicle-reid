## Наша часть

### 1. Задача и почему она не решается номером

Камеры фиксируют миллионы событий, номер часто нечитаем — грязь, блики, ракурс,
перекрытие. Нужен способ узнать ту же машину по внешности.

Здесь же — единственный слайд, где уместно сказать, что задача **сложнее, чем кажется**:
две машины одной модели и цвета внешне неразличимы, и это не недостаток решения, а
свойство задачи. Подготовить почву для честного разбора ошибок в конце.

### 2. Что именно мы сдаём

Схема пользовательского пути (**требование ТЗ разд. 11**):

```
кадр + рамка → кроп → вектор 512 чисел → поиск по галерее →
    → кандидаты с оценкой уверенности  ИЛИ  честный отказ «совпадения нет»
```

Три сдаваемых файла, веб-интерфейс, контейнер, запуск одной командой без интернета.

### 3. Архитектура и обоснование выбора

**Требование ТЗ разд. 11: обосновать выбор backbone и работу с ракурсом и освещением.**

- OSNet-AIN, 8,4 МБ, инференс на CPU — выбран как компактный и быстрый;
- **почему не взяли готовые веса под наш домен:** `fast-reid` с заявленными 81,9 mAP на
  VeRi-776 даёт на московских данных **0,238**. Это наш главный аргумент в пользу
  обучения на данных заказчика, и он подкреплён числом;
- переранжирование добавляет **+0,037 mAP**, не трогая замеряемое время извлечения.

### 4. Как мы не обманули сами себя

Слайд, которого не будет у большинства команд. Три числа:

| | |
|---|---|
| Случайные векторы дают mAP 0,0099 при аналитически ожидаемых 0,0103 | метрика не подыгрывает |
| Без исключения совпадений с камеры запроса Rank-1 подскакивает 0,631 → **0,971** | так выглядит метрика, измеряющая запоминание фона |
| Цена переподгонки параметров названа числом: 0,001–0,012 mAP | подбор и проверка разделены |

Вывод для жюри: наши числа ниже, чем могли бы быть, потому что меряем честно.

### 5. Независимость от государственного знака

**Отдельный слайд, потому что это условие допуска к оценке (ТЗ разд. 9).**

Вклад зоны пластины **не отличим от нуля**: −0,003 mAP при интервале [−0,011; +0,004].
Закрыть пластину оказалось дешевле, чем закрыть такой же прямоугольник рядом на кузове.

Иллюстрация: `04-solution/plate-ablation/pics/detector_vs_labels_*.png` — найденные
пластины против ручной разметки.

Здесь же — честная оговорка, что после дообучения измерение повторено (будет повторено).

### 6. Режим отказа

Почему нельзя брать максимум F1: при 75 % запросов с парой он принимает 86 % чужих —
ровно то поведение, против которого ТЗ вводит TNR.

Наша точка: **F1 0,806, TNR 0,777** [ч]. Цена названа: принимаем 603 запроса с парой из
832 вместо 603→ вместо почти всех, зато ложных принятий 62 вместо 84.

График кривой F1/TNR по порогу — из `04-solution/service/calib/`.

### 7. Разбор ошибок

**Требование ТЗ разд. 11, и одновременно аргумент при равенстве метрик (разд. 10).**

| Причина | доля |
|---|---:|
| смена ракурса | 47 % |
| однотипный кандидат (та же модель и цвет) | 36 % |
| смена освещения | 11 % |
| испорченный кроп | 6 % |

Ключевая мысль: **28 пар машин путаются взаимно — 27 % всех ошибок.** Это предел
признака внешности, а не недоработка. Иллюстрация — `twins_zoom_01.jpg`: две одинаковые
оранжевые машины, различимые только по мелочам отделки.

Отдельно: **примерно каждая двадцатая «ошибка» — дефект разметки датасета**, рамка стоит
на соседней машине. Показать `label_check_*.jpg` с полными кадрами.

**Решено (Артём, 15.09): про дефект разметки говорим.** Подача — как ограничение
измерения, а не претензия: мы объясняем, почему верхняя планка Rank-1 на этих данных
ниже единицы, и показываем, что разбирались в своих ошибках до конца. Формулировку
готовим в двух вариантах, выбираем мягкий.

### 8. Производительность и масштабирование

**Требование ТЗ разд. 11: план масштабирования.**

- извлечение признака: 39–64 мс на объект на CPU, узкое место — декодирование кадра,
  а не сеть;
- веса 8,4 МБ из разрешённых 2 ГБ;
- переранжирование квадратично по памяти, практический потолок около 10⁴ объектов;
  для городского масштаба — приближённый поиск, и здесь нужны числа из задачи о
  масштабировании, когда она закроется.

### 9. Инженерная часть

Микросервисы, OpenAPI, контейнеры, запуск одной командой, инференс без интернета —
проверено прогоном с отрезанной сетью и негативным контролем.

Отдельно стоит показать **аудит воспроизводимости**: документацию писал не тот, кто
делал решение, и он нашёл 18 мест, где сторонний человек спотыкается. Это сильный сигнал
для жюри, которое само будет запускать наш код.

### 10. Планы развития

Что лечится и чем — из разбора ошибок:

- смена ракурса и освещения (≈58 % ошибок) — дообучением;
- двойники (27 %) — только локальными приметами высокого разрешения либо честным
  отказом при малом отрыве;
- дефекты разметки (≈5 %) — ничем на нашей стороне.

Плюс: приближённый поиск для городских объёмов, объяснимость совпадения для оператора.
