# Тексты презентации — сдаваемая конфигурация d1_j48

Источник текстов и заметок докладчика для 15 слайдов. Первые пять страниц сохраняют
обязательный блок шаблона организаторов; разделы 1–10 ниже соответствуют итоговым
слайдам 6–15. Сборка: `python3 build_presentation.py`; проверка:
`python3 validate_presentation.py`.

Обновлено 21.09.2026. **d1_j48**: OSNet-AIN + наш дообученный combined_v1 → L2 каждого
вектора → среднее → L2 → whitening (512 × 512, train_fit, ρ=0,5) → L2.
Пакетный поиск — k-reciprocal (6, 3, 0,3); браузер/API — косинус.

Все значения качества получены на нашей валидации. Метрики закрытого теста неизвестны.
mAP измеряет порядок кандидатов, Rank-1 — долю запросов с верной машиной на первом месте.
Основной протокол — market, вся галерея, 832 запроса с парой из 1110; mAP@10 указан отдельно.
Исторические примеры исходной модели подписаны и не приписываются d1_j48.
`[НЕТ ЗАМЕРА]` означает незавершённую проверку, а не нулевой результат.

Пакетная сдача: переранжирование»**. Одна команда относится к пакетному инференсу после подготовки образа и данных; базовые образы должны быть подготовлены заранее; Python-пакеты приложены.

Для докладчика: браузер/API использует косинусный поиск; batch — KR (6, 3, 0,3). Порог зависит от режима. Оценка близости не является вероятностью.

## 3. Архитектура и обоснование выбора

### Заголовок

**Две модели → 512 чисел: mAP 0,7741**

### Тезисы на слайд

- OSNet-AIN (MIT) + combined_v1 — OSNet-AIN, дообученная нами методом LP-FT.
- Объединённый набор: RoundaboutHD (MIT) + CARLA-ReID (Apache-2.0) + train организатора.
- Общий вход RGB 208 × 208; L2 каждого вектора → среднее → L2 → whitening → L2.
- Whitening: матрица 512 × 512, обучена на train_fit; k-reciprocal (6, 3, 0,3).

### Числа на слайде

|---|---:|---:|
| Косинус — браузер/API | 0,7316 | 0,6851 |
| Переранжирование — пакетная сдача | **0,7741** | **0,7308** |

**Переранжирование: +0,0425 mAP; mAP@10 = 0,7685.**
Прежняя сдаваемая OSNet+KR: mAP 0,6937 / Rank-1 0,6635; прирост mAP **+0,0804**.
Сравнение с прежним чемпионом контура — отдельная строка в разделе 4.

### Иллюстрация

```text

Кроп → RGB 208 × 208 ─────┤                 ├→ L2 каждого → среднее → L2
                          └→ combined_v1 ───┘                         ↓
                                          whitening 512 × 512, train_fit → L2
                                                                      ↓
                                                k-reciprocal (6, 3, 0,3)
                                                                      ↓

```

### Примечание для верстальщика

Сохранить шаблон, цвета и Montserrat. Две ветви модели должны быть явными; стрелки
проходят между блоками и не пересекают текст. Лицензии и происхождение combined_v1
видны на слайде. Подпись: **«Наша валидация: 832 запроса с парой, market, вся галерея.
API — косинус; пакетная сдача — переранжирование»**.

Для докладчика: OSNet-AIN выбран по проверке на нашем сплите и компактности; прежний
контроль FastReID R50-IBN дал 0,238 mAP против 0,657 у исходного OSNet на косинусе.
Это историческое сравнение, не метрики d1_j48. Обе сети содержат нормировку входа;
внешняя ImageNet-нормировка не применяется. После нормировки каждого вектора берём
среднее и снова L2: матрица whitening обучена именно на нормированных входах.
Whitening `(x − m) @ P.T`, ρ=0,5, обучен только на train_fit; затем итоговая L2.
combined_v1 — наш LP-FT исходного OSNet-AIN (MIT) на RoundaboutHD (MIT), CARLA-ReID
(Apache-2.0) и train организатора. Лицензии названы по журналу проекта; полнота цепочки
происхождения всех данных предобучения OSNet остаётся ограничением SOLUTION.md §11.
Ракурс и свет составляют около 58 % в ручном разборе ошибок исходной модели; эта доля
не пересчитана для d1_j48. Качество пакетного режима не приписывать API.

## 7. Разбор ошибок

### Заголовок

**28 пар двойников дают 27 % ошибок первого кандидата**

### Тезисы на слайд

- Базовая модель ошиблась в первом кандидате на **307 из 832** запросов с парой.
- **28 пар** путаются взаимно: A выдаёт B, B выдаёт A. Это **84 из 307 ошибок первого кандидата — 27 %**.
- Переранжирование исправляет **6 %** ошибок двойников против **18 %** остальных. Мелкие приметы требуют отдельной проверки.

|---|---:|
| Смена ракурса | 47 % |
| Та же модель, цвет или ливрея у чужой машины | 36 % |
| Смена освещения | 11 % |
| Испорченный кроп | 6 % |

### Примечание для верстальщика

Взаимная путаница и таблица причин — обязательны. Подпись: **«Базовая модель, до переранжирования; наша валидация»**. Это ограничение исходного признака на этих примерах, а не доказанная невозможность различить автомобили любым методом. Долю 27 % не складывать с 36 %: это разные способы группировать те же ошибки первого кандидата. 27 % — доля ошибок первого кандидата, а не доля потерянной массы AP.
