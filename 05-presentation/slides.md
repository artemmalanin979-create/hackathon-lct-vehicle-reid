# Тексты презентации — сдаваемая конфигурация d1_j48

Источник текстов и заметок докладчика для 16 слайдов. Первые пять страниц сохраняют
обязательный блок шаблона организаторов; разделы 1–11 ниже соответствуют итоговым
слайдам 6–16. Сборка: `python3 build_presentation.py`; проверка:
`python3 validate_presentation.py`.

Обновлено 21.09.2026. **d1_j48**: OSNet-AIN + наш дообученный combined_v1 → L2 каждого
вектора → среднее → L2 → whitening (512 × 512, train_fit, ρ=0,5) → L2.
Пакетный поиск — k-reciprocal (6, 3, 0,3); браузер/API — косинус.

Все значения качества получены на нашей валидации. Метрики закрытого теста неизвестны.
mAP измеряет порядок кандидатов, Rank-1 — долю запросов с верной машиной на первом месте.
Основной протокол — market, вся галерея, 832 запроса с парой из 1110; mAP@10 указан отдельно.
Исторические примеры исходной модели подписаны и не приписываются d1_j48.
`[НЕТ ЗАМЕРА]` означает незавершённую проверку, а не нулевой результат.

Источники: `04-solution/training/combined/s02_metrics.json`, `SOLUTION.md`,
`04-solution/service/README.md`, `04-solution/plate-ablation/d1_j48/REPORT.md`.
README прежней конфигурации `postproc/whitening/final/` источником чисел не является.

## 3. Пользовательский путь при работе с сервисом

### Заголовок

**Пользовательский путь: от кадра к решению**

### Тезисы на слайд

- Подготовка: администратор запускает сервис и загружает галерею; оператор открывает браузер.
- Оператор загружает JPEG/PNG, рисует рамку автомобиля или задаёт x/y/w/h и нажимает «Найти кандидатов».
- Сервис проверяет ввод, вырезает автомобиль, строит признак и ищет ближайших в Qdrant.
- API оставляет только кандидатов с косинусом ≥ порога. Если список пуст — отказ.
- Оператор видит фото, ID, близость и разницу с порогом; открывает полный кадр и выгружает CSV / JSON.

### Иллюстрация

Редактируемая схема с тремя зонами: «Оператор», «Сервис», «Результат».

```text
Подготовка: галерея загружена (в выданном наборе 750 объектов)

ОПЕРАТОР                 СЕРВИС                          РЕЗУЛЬТАТ
JPEG/PNG + рамка ──────→ Проверка ввода
«Найти кандидатов»         ↓
                        Кроп → признак → Qdrant
                        Точный поиск top-10
                          ↓
                        Есть score ≥ t_cos? ── Да ─────→ Карточки: фото, ID,
                          │                              близость, разница с порогом
                          └────────────────── Нет ────→ «Уверенного совпадения нет»

                                                               ↓

```

Ветки «Да» и «Нет» сходятся к экспорту: отказ тоже сохраняется как результат.
Ошибку ввода оператор исправляет; отсутствие галереи или недоступность хранилища
устраняет администратор. Это отдельные состояния, не модельный отказ.

### Примечание для верстальщика

Главный элемент — схема сервиса, без раскрытия нейросети. Ромб — решение в API
**после** поиска, сравнение **≥**, а не строго больше. Число порога подписать
«по умолчанию, округлено»; API допускает пользовательский порог.
На слайде оставить видимыми обе развилки и последующее действие оператора.
Карточки содержат снимки, только если каталог изображений смонтирован.
Внизу явно: «Время ответа d1_j48: [НЕТ ЗАМЕРА]».

Для докладчика: реальное сравнение ведётся с полным порогом 0.5141976914190476,
до округления confidence для ответа. `refusal=true`, `candidates=[]`,
`best_confidence` и применённый `threshold` возвращаются и при отказе.
Точный top_k выбирает Qdrant; затем API фильтрует каждого кандидата.
Состояния 422/409/503 показаны отдельной ошибкой, а не «машины нет».
Оператор может явно запросить кандидатов ниже порога; интерфейс помечает их,
исходный отказ сохраняется. Экспорт браузера при отказе оставляет запись запроса.
Просмотр полного кадра доступен при смонтированных изображениях; наличие кнопки

### Примечание для верстальщика

Схема сверху; ниже — видимые объяснения выбора backbone, работы с ракурсом и светом.
Не прятать их только в заметки. Качество d1_j48 и исторический срез света подписать
раздельно. Оговорка об отсутствии отдельной проверки d1_j48 остаётся на слайде.

Для докладчика: combined_v1 — наш LP-FT OSNet-AIN (MIT) на RoundaboutHD (MIT),
CARLA-ReID (Apache-2.0) и train организатора. Состав и лицензии видны в подписи схемы.
Код рецепта MCNL предпочитает трудный межкамерный позитив; если его нет, берёт
позитив той же ID. Негативы со своей камеры не позволяют решить задачу одним фоном.
MixStyle смешивает статистики признаков после stem и mid. Аугментации — hflip,
pad-crop; это не моделирование произвольного поворота автомобиля.
Whitening обучен на train_fit, по межкамерным разностям признаков; оценки валидации
в его обучение не входят. Общий прирост d1_j48 нельзя приписывать одному MixStyle,
MCNL или конкретно освещению: изолирующих абляций нет. Для ракурса есть исторический
успешный пример v825 на слайде 6, но это не агрегированное доказательство устойчивости.
Все метрики — наша валидация, market, вся галерея; 832 запроса с парой из 1110
(`SOLUTION.md`, §6). KR добавляет +0,0425 mAP, mAP@10=0,7685
(`04-solution/training/combined/s02_metrics.json`). Против OSNet+KR прирост +0,0804;
сравнение с прежним чемпионом контура — раздел 5, итоговый слайд 10.
Нормировка входа встроена в ONNX. Внешняя ImageNet-нормировка не используется;
среднее нормируется до whitening, затем результат вновь L2.
Полнота происхождения предобучения OSNet остаётся ограничением `SOLUTION.md`, §11.

### Ранее проверенные направления — резерв докладчика

Для докладчика (резерв): zero-shot KR mAP: DINOv2-S 0,0687, DINOv2-B 0,0874, CLIP-B 0,1559,

лучшая проба ухудшила mAP примерно на 0,002. Возвращаться к месту имеет смысл при
появлении времени или координат, а не объявлять фон универсально бесполезным.
Ранние две попытки дообучения на данных организатора не дали принятого прироста;
позднее combined_v1 на объединённом наборе вошла в d1_j48. Поэтому старая фраза

исправление примеров разметки, масштабирование ANN с повторной калибровкой отказа.
