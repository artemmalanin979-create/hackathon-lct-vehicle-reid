# Презентация ПРОСВЕТ

ЛЦТ 2026, задача №7 «Фалькон Тех», команда 33. Сборка содержит **16 слайдов**.
Техническая история переработана 25–26.09.2026 и сверена с опубликованным
оценщиком 29.09: реальные кадры финальной d1_j48,
путь пользователя с настоящим экраном сервиса, pipeline, cosine/KR, ошибки/отказ,
стоимость, обученный CrossViewCore и комплект сдачи. Это отдельная MobileNetV3-Small
с собственной global/local головой, а не переименование ансамбля. Ядро быстрее
по ограниченному CPU-замеру, но не прошло критерий качества и отказа; релиз — d1_j48.
Снимок UI и API provenance закреплены хешами в assets/. Итог нового официального
пересчёта d1_j48 и CrossViewCore — в `assets/official-evaluation-20260929.json`:
на повторно использованной val независимый top-50 KR/query даёт mAP@10 0,7411
и 0,2980 соответственно. Старый общий KR-граф с mAP 0,7741 оставлен только
как исторический опыт. Детали обучения ядра — в `assets/owncore-distill-summary.json`.

Шаблон организатора `../00-task/assets/ЛЦТ2026 Шаблон презентации.pptx`:
37 страниц, MD5 `9618b7981babb8cd472d636ebc9bd732`. Обязательные страницы **7–11**
остаются итоговыми 1–5, с исходной геометрией полей, логотипами, темой и Montserrat.
Командные контакты читаются из локального `team-data.md` и находятся только на слайде 3.
Полный PPTX и PDF нельзя включать в Git или публичные screenshots.

Решение отправлено через платформу 28.09.2026. Обновлять материалы по указанным
ссылкам можно строго до **29 сентября, 23:59**; коммиты после этого срока

## Сборка и проверка

Из корня репозитория должны присутствовать локальный `05-presentation/team-data.md`
и предоставленные организатором JPEG для показанного случая N02 в `data/images/`.
В Git контактные данные и исходный датасет не включаются.

```bash
python3 05-presentation/build_presentation.py
python3 05-presentation/validate_presentation.py
python3 05-presentation/test_submission_contract.py
python3 05-presentation/render_review.py
python3 05-presentation/check_ui_provenance.py
```

Последняя команда сравнивает зафиксированный браузерный снимок и его исходники с
текущими файлами сервиса. Штатные build и validate выполняют эту проверку в начале
и останавливаются при расхождении. Снимок получен 28.09 из интегрированного UI
`6e8c1c9` через `capture_proxy.py` к развёрнутому API d1_j48 с 750 объектами
галереи. После изменения методического текста `index.html` в `71ee4e4` он
повторно снят 29.09 с текущим UI и тем же API: 44 отличающихся пикселя из
1 440 000, содержимое рабочего экрана совпадает. Первый пример `e03daa7c…`
имеет полный bbox; видимые первые кандидаты сняты иначе, чем запрос. В захвате
обе темы прошли путь поиск → сравнение → разбор → отказ. Хеши исходников,
скриптов, PNG и версия модели — в
`assets/ui-provenance.json`; test без меток не подтверждает личность найденного ТС.

В отдельном deck worktree без интегрированного UI нужно задать
`LCT_PRESENTATION_UI_REPO=/абсолютный/путь/к/интегрированному/checkout` для
этой проверки. Полная финальная сборка выполняется после переноса deck-коммитов
в интегрированное дерево, где переменная не требуется.

Зависимости: python-pptx, Pillow, lxml, Montserrat, LibreOffice headless, pdftotext,
pdfinfo. Сборщик использует существующий стек проекта, без сети. Validator запускает
изолированный профиль LibreOffice (`LCT_LIBREOFFICE` задаёт абсолютный путь бинарника).

Выходы, исключённые из Git:

- `ЛЦТ2026-задача7-ПРОСВЕТ.pptx` — редактируемая полная презентация.
- `checks/ЛЦТ2026-задача7-ПРОСВЕТ.pdf` — полный PDF, **16 страниц**, с контактами.
- `checks/content_preview.pptx` и `.pdf` — 11 технических страниц, без контактов.
- `checks/validation.json`, `full_render_check.json`, `render_check.json` — машинная приёмка.

Validator проверяет тему и 57 исходных геометрий обязательного блока, шрифт,
встроенные изображения и их точные исходные пиксели, отсутствие внешних ссылок на
изображения, текст во всех 16 страницах PDF и независимый page count через pdfinfo.
Три штатных теста проверяют контракт submission/embeddings/candidates в builder и обоих PPTX.

Текущий статус сборки, визуальной проверки и публикации —
[build-report.md](build-report.md). Публичная копия `https://iamcp.ru/submission/`
должна быть сверена с SHA нового локального PPTX/PDF после развёртывания.
