## Сборка и проверка

Из корня репозитория, локально должен присутствовать `05-presentation/team-data.md`:

```bash
python3 05-presentation/build_presentation.py
python3 05-presentation/validate_presentation.py
python3 05-presentation/test_submission_contract.py
python3 05-presentation/render_review.py
python3 05-presentation/check_ui_provenance.py
```

Последняя команда сравнивает зафиксированный браузерный снимок и его исходники с
текущими файлами сервиса. Штатные build и validate выполняют эту проверку в начале
и останавливаются при расхождении. Снимок обновлён 26.09 из интегрированного UI
`d94d3fd` через `capture_proxy.py` к настоящему API d1_j48 с 750 объектами
галереи. В захвате обе темы прошли путь поиск → сравнение → разбор → отказ;
десять кадров и локальный протокол запросов сохранены в ignored `checks/capture/`.
Хеши исходников, скриптов, PNG и версия модели — в `assets/ui-provenance.json`.

В отдельном deck worktree без интегрированного UI нужно задать
`LCT_PRESENTATION_UI_REPO=/абсолютный/путь/к/интегрированному/checkout` для
этой проверки. Полная финальная сборка выполняется после переноса deck-коммитов
в интегрированное дерево, где переменная не требуется.

Зависимости: python-pptx, Pillow, lxml, Montserrat, LibreOffice headless, pdftotext,
pdfinfo. Сборщик использует существующий стек проекта, без сети. Validator запускает
изолированный профиль LibreOffice (`LCT_LIBREOFFICE` задаёт абсолютный путь бинарника).

Выходы, исключённые из Git:

- `ЛЦТ2026-задача7-ПРОСВЕТ.pptx` — редактируемая полная презентация.
- `checks/ЛЦТ2026-задача7-ПРОСВЕТ.pdf` — полный PDF, **16 страниц**, с контактами.
- `checks/content_preview.pptx` и `.pdf` — 11 технических страниц, без контактов.
- `checks/validation.json`, `full_render_check.json`, `render_check.json` — машинная приёмка.

Validator проверяет тему и 57 исходных геометрий обязательного блока, шрифт,
встроенные изображения и их точные исходные пиксели, отсутствие внешних ссылок на
изображения, текст во всех 16 страницах PDF и независимый page count через pdfinfo.
Три штатных теста проверяют контракт submission/embeddings/candidates в builder и обоих PPTX.

Вкус и готовность к показу принимает независимый визуальный критик, затем Артём.
Публикация сервиса, передача ссылок жюри и загрузка презентации проверяются отдельно.
