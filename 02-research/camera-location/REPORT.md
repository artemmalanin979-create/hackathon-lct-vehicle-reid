# job_47 — сигнал «камера → место» из пикселей фона: измерение

Дата: 2026-09-18. Узел: worker-vm. Данные: только наш валидационный контур (1860 кадров, 90 камер).
Это измерение, не фича. Метрики — только контуром `04-solution/eval/reid_metrics.py`
(camera_policy=market, refusal=presence), те же вектора и тот же контур, что job_45.

## TL;DR

1. **Сигнал «камера → фон» есть.** По замаскированному фону кадр относится к своей камере
   (90 классов) с top-1 = 50,7% / top-5 = 70,4% (thumbnail 48×48); HSV-гистограмма — 40,2/66,8;
   эмбеддинг ReID-модели по замаскированному кадру — 38,9/62,3. Шанс 1/90 ≈ 1,1%.
   Медианный ранг истинной камеры 1–3. Фон у камеры стабилен.
2. **Сигнал «камера → место» (группы камер одной локации) — НЕ обнаружен.** Межкамерное
   сходство фонов — сплошной континуум: средний косинус прототипов чужих камер 0,958 (thumbnail),
   что выше «плохого» внутрикамерного уровня (p10 = 0,87). Визуально проверены самые похожие
   межкамерные пары (включая 7 пар с q95 ≥ 0,99 по кадрам) — **ни одна не является одним местом**;
   верхние пары — разные улицы с родственной «центр-города» текстурой, камера 55 (размытая)
   «похожа на всех». Кластеризация по фону даёт либо 2 сгустка-континуума, либо цветовые blobs;
   консенсус ≥2 дескрипторов из 3 на строгом пороге — 0 пар.
3. **Пользы для метрики нет, механизму нечего ловить.** На финальной конфигурации (d1_w1.0,
   mAP=0.7621): доля top-1 ошибок с «несовместимой локацией» неотличима от таковой у верных
   ответов (63,0% против 64,7% по hsv-кластерам; 17,9% против 17,3% по thumb-кластерам).
   Любое вмешательство (hard-drop или штраф λ∈[0,05; 2,0] в обе стороны, обе разметки)
   **монотонно ухудшает mAP**; лучшая из всех проб −0,002. Hard-drop в любую сторону: −0,10…−0,62.
   Отклонения от случайных контролей — ±0,08, меньше абсолютного ущерба на порядок.

**Вердикт:** из пикселей фона «места» построить нельзя — существует per-camera фоновый
отпечаток, но не location-структура; при нашем протоколе (same-camera пары уже исключены)
из сигнала нечего извлечь: он не различает ошибки и верные ответы. Предложение
«совместимость по месту» из пикселей закрыто; возвращаться к нему имеет смысл только при
появлении времени/координат в данных.

## 1. Стабильность фона и отнесение кадра к камере

Метод: bbox (x,y,w,h) + маржа 3% замаскирован заливкой средним цветом фона (проверено
визуально — чисто). Три независимых дескриптора фона: thumbnail 48×48 RGB (6912d, L2),
HSV-гистограмма 24×8×8 по немаскированным пикселям (с весом S, L1 → сходство = пересечение),
эмбеддинг ain_v2_s2 по замаскированному кадру 208². Отнесение к камере — leave-one-out:
прототип камеры = среднее векторов её прочих кадров; ранг истинной камеры среди 90.

| дескриптор | top-1 | top-5 | медианный ранг | истина в top-10 | same-vs-diff AUC пар |
|---|---|---|---|---|---|
| thumb 48×48 | **0,507** | **0,704** | 1,0 | 79,2% | 0,599 |
| HSV-гистограмма | 0,402 | 0,668 | 2,0 | 78,7% | 0,685 |
| ain_v2 по фону | 0,389 | 0,623 | 3,0 | 74,8% | 0,604 |

Контраст same-vs-diff: средний косинус пары кадров одной камеры 0,910 (p10 = 0,843) против
0,897 (p90 = 0,948) для чужих камер — распределения сильно перекрываются: фон идентифицирует
камеру статистически, но не жёстко (освещение/погода двигают и внутрикамерное сходство).

Оценивались 1855 кадров (у 5 камер по 1 кадру — не оцениваются). 10 камер с top-1 ≥ 0,9
(«уникальный» фон), 15 камер с top-1 < 0,3 (генерические улицы). Полная таблица по 90 камерам:
`out/s11_cam_table.json`, см. Приложение (top-1 thumb/hsv/ainv2, медианный ранг).

## 2. Кластеры камер = «места»

Кластеризация прототипов камер (агломеративная, average-linkage, косинус; k по силуэту):
- thumb и ainv2: силуэт выбирает **k=2** (89+1) — один выброс против континуума;
- hsv: **k=18**, размеры [32, 22, 15, 4, 3, 2, 1×11] — цветовые blobs, не места;
- согласие попарных кластеризаций между дескрипторами: thumb↔hsv 0,23, hsv↔ainv2 0,23,
  thumb↔ainv2 0,96 (оба — «всё в одном сгустке + выброс»); **консенсус 2-из-3 на τ=0,98: 0 пар**.

Пороговые компоненты (прототипный косинус ≥ τ, thumb): τ=0,995 → 83 компоненты [7,2,1…];
τ=0,99 → 56 [35,1…]; τ=0,98 → 30 [61,1…]; τ=0,95 → 6 [85,1…]. По кадровому q95 ≥ 0,99 —
7 пар (все включают размытую камеру 55). **Визуальная проверка** (`out/s12c_pairs.png`):
строгие пары и пары cos∈[0,98;0,995) — разные физические места (см. TL;DR п.2).
Репер внутрикамерный (p10 попарных косинусов кадров камеры на себя) по thumb: медиана 0,87,
минимум 0,61 — т.е. «своё место» камера помнит хуже, чем похожа на другие камеры.

Вывод шага: «мест» как компактных групп камер в данных нет; есть per-camera отпечаток
и глобальное «похоже на центр города».

## 3. Польза для метрики (честно)

Протокол: финальная конфигурация job_45 **d1_w1.0** (KR 6/3/0.3, market), контроль
mAP = 0,76206 / R1 = 0,7175 на 832 known-запросах — совпало с таблицей job_45.
Проверены две «best-effort» разметки мест: hsv-k18 (§2) и thumb-τ0.98 (61-кам мега-blob).
Вмешательства на матрице скоров KR: hard-drop и аддитивный штраф λ∈[0,05…2,0] в обе стороны,
плюс 25 случайных разметок с теми же размерами кластеров как контроль.

Диагностика top-1 (235 ошибок из 832):

| разметка | ошибок «несовм. локации» | верных в своём кластере | ВСЕ позитивы в чужом | ВСЕ позитивы в своём |
|---|---|---|---|---|
| hsv-k18 | 148 (63,0%) | 211/597 (35,4%) | 487/832 (58,5%) | 179/832 (21,5%) |
| thumb-τ0.98 | 42 (17,9%) | 494/597 (82,7%) | 112/832 (13,5%) | 653/832 (78,5%) |

Ключевое: **P(кросс-кластер | ошибка) ≈ P(кросс-кластер | верный ответ)** — 63,0% против
64,7% (hsv) и 17,9% против 17,3% (thumb). Метка «несовместимости» не обогащает ошибки:
сигнала для rerank-приоритета нет.

Эффект на mAP (база 0,7621):

| вмешательство | hsv-k18 | thumb-τ0.98 | случайный контроль (mean±std) |
|---|---|---|---|
| hard-drop чужого кластера | 0,2836 | 0,6659 | 0,199±0,067 / 0,380±0,067 |
| hard-drop своего кластера | 0,5388 | 0,1467 | 0,617±0,061 / 0,449±0,069 |
| штраф своего, λ=0,05…2,0 | 0,7593 → 0,5388 (монотонно вниз) | 0,7462 → 0,1467 (монотонно вниз) | — |
| штраф чужого, λ=0,05…2,0 | 0,7431 → 0,2836 (монотонно вниз) | 0,7599 → 0,6659 (монотонно вниз) | — |

Лучшая из всех проб: −0,0022 к mAP (λ=0,05). Реальный эффект vs случайный контроль:
hsv hard-drop чужого +0,084 above random mean (~1,3σ), hard-drop своего −0,078 (~1,3σ);
thumb +0,286/−0,303 (структурный артефакт мега-blob: «свой кластер» = «2/3 всех камер»).
Любая разумная интерпретация — в пределах шума и несопоставима с абсолютным ущербом.

Почему так: мейты в валидации почти всегда кросс-камерные (357/369 ТС в >1 камере), а
«места» не существует — у 58,5% (hsv) / 13,5% (thumb) known-запросов все позитивы лежат
внутри одного кластера, и любой кросс-кластерный фильтр их обнуляет.

## 4. Вердикт

- Сигнал «камера → фон»: **есть** (top-1 51%/top-5 70% из 90).
- Сигнал «камера → место» (группы камер одной локации): **не обнаружен** — континуум
  родственных уличных фонов, 0 подтверждённых визуально пар «одно место», 0 консенсусных
  слияний между независимыми дескрипторами.
- «Совместимость точек» из пикселей построить нельзя; при протоколе с исключёнными
  same-camera парами сигналу **нечего ловить**: он не различает ошибки и верные ответы,
  любое использование монотонно портит mAP.
- Рекомендация (измерения ради, без предложений фич): гипотеза Артёма проверена и закрыта
  для пиксельного варианта; единственный оставшийся путь к «контексту точки» — метаданные
  (время/координаты), которых в сплите нет.
