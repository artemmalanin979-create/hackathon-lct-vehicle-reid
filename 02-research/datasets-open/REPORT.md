   прошлого отчёта; CARLA идёт вторым (синтетика, Apache на репозиторий, данные на Dropbox
   без отдельного файла лицензии).
2. **Классические vehicle-reID (VeRi-776, VERI-Wild, VehicleID, CityFlow) — все
   research-only / non-commercial.** Зеркала без логина сегодня в основном закрыты

   файла (не квоту/бан) — то есть **фактически качаются анонимно** через confirm-токен
   (`gdown`; в этой VM нужен системный CA — venv-certifi не верит Google из-за
   перехватывающего прокси). Итог: «без письма» — да, но канал один (GDrive) и лицензия
   некоммерческая.
3. **Обучать на CPU нельзя.** Замер на узле: форвард OSNet ~1.3–3.2 img/s (нет FMA под
   VirtualBox + чужая нагрузка). Полный рецепт на объединённом наборе на этом CPU — сотни
   часов (§3). Правило брифа «>8 ч → не запускать» срабатывает с огромным запасом. Всё
   подготовлено к запуску на GPU; на современной облачной карте весь рецепт — 1–3 ч.
4. **Допуск (ТЗ разд. 7).** Основной риск — не «внешние данные вообще» (они разрешены и
   приветствуются), а «**закрытые, проприетарные или невоспроизводимые**». Датасеты «по
   письму/подписи» (VeRi, VERI-Wild, VehicleID, PKU-VD) — воспроизводимы жюри плохо и несут
   риск. Свободно качаемые (RoundaboutHD, CARLA) — воспроизводимы и безопасны для допуска
   **и** для коммерческой поставки весов.
5. **Важная оговорка из собственного ресёрча репозитория** (`02-research/training-v2/`):
   рецептурная ветка измеряет наивное смешивание чужих данных как **−3,8 mAP** и советует
   внешние данные **не брать**, а вложиться в постобработку (камерный штраф +3,8, re-rank).
   Гипотеза брифа («мало данных») проверяется именно против этого. Мой объединённый набор
   уважает правило DMT (чужих ID ≤ своих): RoundaboutHD 511 + CARLA 650 ≈ 1161 ≲ наши 1171.

## 3. Обучение: оценка времени и готовность к GPU

### 3.1. Замер скорости на узле (факт, сегодня)

Форвард базового OSNet-AIN (`osnet_ain_x1_0_vehicle_reid.onnx`, sha256
`4aaad3e5…c92d91f` — совпал с паспортом), вход 3×208×208, onnxruntime 1.30, CPU EP:

| режим | throughput | load во время |
|---|---:|---|
| 1 поток, B=16 | **3,18 img/s** | 6,5 |
| 4 потока, B=32 | **1,27 img/s** | 10,3 |

Два независимых тормоза: (1) VirtualBox **маскирует FMA** (`/proc/cpuinfo`: `avx avx2
sse4_1 sse4_2`, **без `fma`/`f16c`**) — свёртки без FMA кратно медленнее; (2) 4 потока
поверх чужих ~6 на 8 vCPU дают **оверсабскрайб** и трешинг — поэтому 4 потока тут *хуже*
одного. Разрешённый лимит (4 потока, `taskset -c 0-3`) на этом хосте контрпродуктивен.

### 3.2. Оценка времени обучения на CPU

Обучение (fwd+bwd+optim) ≈ 3× форварда → **0,4–1,1 img/s** на этом хосте.

| набор | проходов (imgs×эпох) | при 1 img/s | при 0,4 img/s |
|---|---:|---:|---:|
| только наши (7 248 × 30) | 217 440 | **60 ч** | 151 ч |
| **объединённый собранный (20 576 × 23)** | 473 248 | **131 ч** | 328 ч |

(23 эпохи = трёхступенчатое расписание 5+12+6.) Даже в теоретически идеальном случае (без
контенции, 4 потока масштабируются, ~12 img/s форвард → ~4 img/s обучение) наш маленький
набор за 30 эпох — **~15 ч > 8 ч**, а собранный объединённый — **≥ 33 ч**. **Вывод: на CPU
не запускаем** (правило брифа «>8 ч → не запускать»), готовим к GPU.

### 3.3. Что подготовлено к запуску на GPU

- **Объединённый набор СОБРАН** (§5): `combined_train.npz` + `combined_crops_208.npy` —
  20 576 кадров, 2 287 ID, 114 камер (наши + CARLA + RoundaboutHD), 91 % ID с ≥2 камерами,
  общее пространство ID/камер, правило DMT соблюдено. Проверен загрузкой. Хэши — в §5.
- **Рецепт** (`02-research/training-v2/recipe.md`, кратко): старт с весов
  `vehicle-reid-0001` (вынуть из ONNX), **сэмплер MCNL** (позитив — с ДРУГОЙ камеры,
  сложнейший негатив — из СВОЕЙ камеры; батч C=4×P'=4×K=4=64), **BNNeck + label smoothing +
  warmup**, **снять Random Erasing**, MixStyle после res1+res2, трёхступенчатое расписание
  с воротами (LP → разморозка верха → полная), метрики — только наш контур
  `04-solution/eval/`.
- **Что нужно от GPU**: карта ≥8 ГБ (любая современная — Maxwell-ограничения из recipe.md
  §6.4, т.е. torch≤2.14/cu126, к облачной карте **не относятся**), CUDA-torch, ~30–60 мин на
  прогон. Оценка полного цикла (3 ступени + абляции) на T4/A100 — **1–3 ч**.
- **Оценка по GPU из репо** (Maxwell M2000M, §6.3): OSNet-AIN@208 batch24 = 168–241 с/эп на
  7 248 кадрах = 30–43 img/s; полный 30-эп. цикл 1,4–2 ч даже на слабой карте.

Ссылка по камере после обучения: разрыв (без исключения − честный) должен быть **≤ +0,156**
(у готовых весов). Если больше — модель выучила камеру, прогон убить (правило приёмки §8.4).

## 4. Оценка риска допуска (ТЗ разд. 7)

Цитата ТЗ: «Использование публичных предобученных весов и сторонних открытых датасетов
разрешено и приветствуется… Решения, опирающиеся на **закрытые, проприетарные или
невоспроизводимые** данные, к итоговой оценке не допускаются.»

Две независимые оси — их важно не путать:

| ось | вопрос | последствие |
|---|---|---|
| **Допуск** | воспроизводимо ли жюри свободно и без письма? | «по запросу/подписи» = **невоспроизводимо** → риск дисквалификации |
| **Поставка весов** | разрешает ли лицензия коммерческое использование (и весов)? | non-commercial = нельзя отдать заказчику |

| Датасет | Допуск | Поставка весов заказчику |
|---|---|---|
| **RoundaboutHD** | **Безопасен** (свободно качается) | **Разрешено** (MIT, оговорка §6) |
| **CARLA-ReID** | **Безопасен** (свободно качается) | **Разрешено** (Apache-2.0, оговорка §6) |
| VeRi-776, VERI-Wild | Риск (письмо/некоммерч.; сегодня только GDrive) | **Запрещено** (non-commercial) |
| CityFlowV2, VehicleX | Риск | **Запрещено** — NVIDIA запрещает и **веса** |
| VehicleID, PKU-VD | **Высокий риск** (подпись + академ. почта) | Запрещено |

**Практический вывод (два контура):**
- **Основной контур** (максимум метрики на хакатоне): можно доучить на всём, включая
  CityFlow/VERI-Wild — но в Readme честно перечислить источники, и это **не** тот артефакт,
  что уходит заказчику.
- **Поставочный/допусковый контур** (безопасный): данные заказчика + **RoundaboutHD +
  CARLA-ReID** + ImageNet/`vehicle-reid-0001`. Метрика ниже, зато без риска дисквалификации
  и без юридических проблем при передаче весов.
- Шаг 3 брифа выполняется буквально: если лучший результат окажется на датасете «по
  запросу» (CityFlow/VERI-Wild), **обязателен запасной** на свободном (RoundaboutHD+CARLA);
  оба числа — в отчёт. Пока чисел обучения нет (GPU ждём), оба контура подготовлены.

Отдельно: зеркала на Kaggle/HF **не меняют лицензию** первоисточника — юридически действует
условие авторов, а не метка заливщика.

1. **Лицензия RoundaboutHD**: в карточке Bath поле подписано «**Software**: MIT» и относится
   к записи целиком; отдельного файла лицензии на *данные* нет. MIT — единственное явное
   утверждение, формулировка «Software» оставляет зазор → перед коммерческим использованием
   написать авторам.
2. **Лицензия CARLA-ReID**: Apache-2.0 — это лицензия *репозитория* (LICENSE есть, GitHub
   API подтверждает `spdx: Apache-2.0`); данные лежат на Dropbox без отдельного файла
   лицензии. Что Apache покрывает и данные — вывод по контексту (репозиторий датасетный).
3. **VeRi/CityFlow «доступны сейчас»**: прошлый ресёрч заявлял прямые ссылки; сегодня
   анонимно открылся только GDrive-путь (Kaggle-API 404 без токена, Baidu-BOS/Bath таймаут).
   То есть «без письма» — да, но фактически только через один флакующий канал.
4. **Число ID/камер** для незагруженных датасетов — из прошлого ресёрча/статей, не проверено
   лично в этом прогоне (проверяю только у того, что скачал).
