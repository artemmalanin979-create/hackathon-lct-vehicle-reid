# Готовность к запуску на GPU (объединённый набор)

Обучение на CPU узла невозможно (см. REPORT.md §3: 0,4–1,1 img/s → сотни часов). Ниже —
всё, что нужно, чтобы запустить рецепт на GPU, как только появится карта (Yandex Cloud).
Пайплайн **уже написан** в `04-solution/training/attempt-2/` — переиспользуем его, меняя
только источник данных на объединённый набор.

## Что нужно от GPU-узла

- Карта **≥ 8 ГБ** (любая современная — T4/A10/A100/L4/…). Ограничения Maxwell из
  `recipe.md §6.4` (torch ≤ 2.14, cu126, sm_50) относились к старому узлу с Quadro M2000M и
  к **облачной карте не применяются** — ставить свежий `torch` под CUDA карты.
- `torch`, `torchvision`, `numpy`, `pillow`, `onnx`/`onnxruntime` (для экспорта и сверки).
- Проверка окружения: `python attempt-2/check_gpu.py` — печатает карту, `arch_supported`,
  прогоняет conv fwd+bwd и sgemm. Должно быть `is_available: true`, `arch_supported: true`.

## Артефакты, подготовленные этим заданием (на узле `~/lct-reid/jobs/job_44/`)

- `combined_train.npz` — **собран**: 20 576 кадров, 2 287 ID, 114 камер (наши 7248 + CARLA
  7260 + RoundaboutHD 6068), схема `train_crops.npz` + поле `source`.
  sha256 `c1ee49de…42652c`.
- `combined_crops_208.npy` — сырые кропы 208×208 uint8, **в том же порядке** (наши, затем
  CARLA, затем RoundaboutHD). Именно этот файл читает `reid_train4.py`.
  sha256 `babd228f…3521cc`.
- `build_combined.py` — сборщик (повторяемо; правило DMT соблюдено: чужих ID 1116 ≤ 1171).
- Проверено: 91 % ID имеют ≥2 камеры (кросс-камерный сигнал для сэмплера MCNL).

Порядок и офсеты: наши ID/камеры без изменений; открытые ID сдвинуты в непересекающиеся
диапазоны (RoundaboutHD +100000/cam+1000, CARLA +200000/cam+2000), чтобы сэмплер MCNL
считал их отдельными камерами.

## Шаги на GPU-узле

```bash
# 0. Разложить данные так, как ждёт загрузчик reid_train4.py (ROOT/data/…)
#    combined_train.npz -> $ROOT/data/train_crops.npz
#    combined_crops_208.npy -> $ROOT/data/crops_208.npy
#    (или поправить два пути в load_crops(); ROOT в шапке скрипта.)

# 1. Стартовые веса из ONNX (vehicle-reid-0001 = те, что дают 0,657) -> osnet_ain_start.pt
python attempt-2/build_from_onnx.py --npz osnet_ain_params.npz --save $ROOT/osnet_ain_start.pt
#    (осторожно: build_from_onnx проверяет совпадение имён state_dict с ONNX и
#     сверяет выход torch с ONNX на боевых кропах — это приёмка старта.)

# 2. Трёхступенчатое расписание с воротами (recipe.md §7.6). Батч C·P·K = 4·4·4 = 64.
#    Этап 1 — линейный пробинг (только классификатор + BNNeck), бэкбон заморожен:
python attempt-2/reid_train4.py --run comb --stage 1 --epochs 5  --freeze-fc \
    --init osnet_ain_start.pt --C 4 --P 4 --K 4 --own-k 2 --lr 3.5e-4
#    Ворота: dev mAP не ниже 0,6566 − 0,027, иначе рецепт неверен.

#    Этап 2 — разморозить верхние блоки, бэкбон 0,1×LR:
python attempt-2/reid_train4.py --run comb --stage 2 --epochs 12 \
    --resume-from stage1_ckpt.pt --C 4 --P 4 --K 4 --own-k 2 --lr 3.5e-4
#    Ворота: камерный разрыв (§8, cam-diag) НЕ растёт, иначе убить прогон.

#    Этап 3 — полная разморозка, очень низкий LR (только если этап 2 дал прирост):
python attempt-2/reid_train4.py --run comb --stage 3 --epochs 6 \
    --resume-from stage2_ckpt.pt --lr 2e-5

# 3. Экспорт + сверка + метрики ТОЛЬКО нашим контуром:
python attempt-2/export_onnx.py            # + побитовая сверка torch↔onnx
python attempt-2/eval_table.py             # mAP/Rank-1, с камерой и без
python attempt-2/boot.py                   # парный бутстрэп против 0,694 (σ=0,0134)
python attempt-2/cam_penalty.py            # опц.: камерный штраф VOC-ReID (+3,8 у attempt-2)
```

## Правило приёмки (recipe.md §8.4) — применить к результату

| честный mAP | камерный разрыв (без искл. − честный) | вердикт |
|---|---|---|
| ↑ | ↓ или без изменений | **принять** |
| ↑ | ↑ | отклонить — снова выучила фон/камеру |
| не изм. | ↓ | принять условно (устойчивость выше) |
| ↓ | любой | отклонить |

Опоры: готовые веса — разрыв **+0,156** (mAP), кросс-кам. Rank-1 0,631. Провал №1 — +0,265.
attempt-2 (наши данные) — разрыв +0,161, mAP 0,700 (Δ+0,0064, p=0,52 — **не значимо**).
Цель этого прогона: тот же рецепт **+ открытые данные** сдвинет ли Δ за пределы 2–3σ.

## Оценка времени на GPU

- Референс с Maxwell M2000M (recipe.md §6.3): OSNet-AIN@208 batch24 ≈ 168–241 с/эп на 7 248
  кадрах ⇒ 30–43 img/s. Наш собранный набор — 20 576 кадров (×2,84).
- На современной карте (T4 ≈ 8× Maxwell в этом классе задач) весь трёхступенчатый цикл
  (5+12+6 = 23 эпохи) на 20 576 кадрах — ориентировочно **1–3 ч**, плюс экспорт/оценка.
- Чекпойнт каждую эпоху (в скрипте есть `stageN_ckpt.pt`), так что обрыв не теряет прогон.
