# Измерительный контур

Независимая реализация метрик протокола повторной идентификации. Написана **до** любой
модели и **отдельно** от кода обучения — по правилу из
[`../../02-research/evaluation.md`](../../02-research/evaluation.md): тот, кто учит
модель, не должен единолично контролировать, чем её меряют.

## Зачем это, если организатор обещал свой скрипт

Эталонный скрипт организатора на 15.09 не опубликован. Но главное — даже когда он
появится, нам нужно, с чем его сверить: расхождения между распространёнными
реализациями mAP в re-id доходят **до нескольких десятых на одних и тех же данных**
(разбор — в [`../../02-research/metrics-protocol.md`](../../02-research/metrics-protocol.md),
раздел 9). Совпадения одной итоговой цифры мало: ошибки компенсируют друг друга, поэтому
`compare_results.py` сверяет протокол, статусы запросов, ранги всех верных совпадений,
AP/INP и счётчики.

## Что считает

Ранжирование: mAP, Rank-1, Rank-5, mINP.
Режим отказа при заданном пороге: precision, recall, F1, TNR, AUC-PR.
Исключение совпадений с камеры запроса — обе распространённые трактовки, переключателем.

## Как проверено

| Проверка | Результат |
|---|---|
| Модульные тесты | **60**, все проходят |
| Поломки, которые обязаны ловиться | **25 из 25** — включая 10, найденных независимым разбором |
| Все поля против независимого оракула на точных дробях | 6000 конфигураций прежних полей + 1800 новых, расхождений 0 |
| Сверка с реализациями fast-reid и torchreid на настоящих ничьих | максимальное расхождение mAP 5,6·10⁻¹⁷ |
| Случайные близости против аналитически ожидаемого случайного уровня | в пределах шума |

Последняя строка — ответ на вопрос «как это выглядит, когда сломано»: на случайном входе
метрика обязана показывать случайный уровень, а не что-нибудь лестное.

Таблица «какая поломка каким тестом поймана» — [`mutation_matrix.md`](mutation_matrix.md),
аналитические оракулы — [`ORACLES.md`](ORACLES.md). Первый разбор независимой стороной и
доработка по нему — [`review/`](review/).

## Считает обе ветки сразу — и это принципиально

Контур **всегда** выдаёт метрику по полной галерее и метрику по усечённому списку
(K = 10 — столько кандидатов на запрос принимает `submission.csv`). Их легко перепутать,
а расходятся они сильно: для запроса, чьё верное совпадение стоит на 12-й позиции, по
полной галерее mAP равен 0,083, а по сдаваемому файлу — **ноль**.

Так же устроены все места, где число зависит от трактовки требований, а не от кода.
Организатор пока не ответил, поэтому ни одна трактовка не объявлена правильной —
считаются **обе**, рядом, с числами:

| Развилка | Ветка А | Ветка Б |
|---|---|---|
| Знаменатель AP при усечении | все верные в галерее: 0,25 | только попавшие в список: 0,5 |
| Усреднять mAP по запросам с совпадением или по всем | 1,0 | 0,5 |
| Запрос, у которого все совпадения отфильтрованы по камере | выбросить: TNR не определён | считать «совпадения нет»: TNR = 1 |
| mINP, когда последнее совпадение не попало в список | не определён | ноль |
| Rank-5 при K = 2 | не определён | 1,0 |
| **Что раньше: отбор десятки или исключение по камере** | сначала десятка: **0** | сначала исключение: **0,5** |

Последняя строка — не теоретическая: порядок этих двух операций меняет метрику вдвое.
Это вопрос A4 к постановщику.

## Точность

Считаем в float64, переводя координаты эмбеддингов до нормировки. Причина в числе:
поломка с квантованием близостей во float32 меняла mAP с 0,5 на **1,0** — в лестную
сторону — и не ловилась ничем. Косинусы соседних изображений различаются на величины
порядка 3·10⁻⁸ при шаге float32 около 6·10⁻⁸, то есть во float32 они схлопываются в
ничью, и порядок начинает определять расположение столбцов.

Совпавшие после округления значения ничьей объявляются честно: по округлённому входу
узнать, какое из двух исходных было больше, невозможно.

## Запуск

```bash
python -B -m unittest -v test_metrics   # тесты
python -B verify.py                     # полная проверка, включая мутации
```

Зависимости — только numpy. Сети не требует.

## Происхождение

Реализация выполнена независимым исполнителем по спецификации задачи, без доступа к
нашим ожиданиям по числам. Затем разобрана **другой** независимой стороной, которой
тоже не сообщали, что мы считаем правильным, — она предъявила 10 поломок, проходивших
все прежние проверки. После этого контур доработан автором по её находкам.

История: [`review/critique-01.md`](review/critique-01.md) — разбор,
[`review/rework-01.md`](review/rework-01.md) — доработка.
