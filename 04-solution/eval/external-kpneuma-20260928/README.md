## Что измерено

[KPNEUMA от авторов](https://github.com/yuratak/ReID) содержит кропы отдельных
машин. Взяты все 318 `images_query` и 318 `images_gallery`, без train-каталогов.
У каждого запроса ровно одна галерейная пара с той же идентичностью и другим
Virtual Loop Detector. Оба кадра могут относиться к одной аэросъёмке и одной
траектории: VLD **не эквивалентен разным физическим камерам ЛЦТ**. Поскольку
положительная пара одна, AP для запроса равен `1 / rank`; здесь mAP также равен
среднему обратному рангу. Данные не использовались при обучении наших весов.

| Полная галерея, 318 запросов с парой | mAP | 95% bootstrap по ID | Rank-1 | Rank-5 |
|---|---:|---:|---:|---:|
| d1_j48, cosine | 0,490256 | [0,442709; 0,536601] | 0,383648 | 0,603774 |
| d1_j48, KR 6/3/0.3 | 0,406962 | [0,361534; 0,450829] | 0,286164 | 0,525157 |
| Случайные независимые 512D признаки, cosine | 0,025802 | — | 0,006289 | 0,028302 |
| Идеальное ранжирование по меткам (контроль) | 1,000000 | — | 1,000000 | 1,000000 |

Признаки сформированы **тем же** `Embedder` сервиса из обоих ONNX и whitening:
полный PNG-кроп → RGB 208×208 → 512D. Ранжирование — функции сервиса;
подсчёт mAP/Rank — существующий независимый контур `eval/reid_metrics.py`.
Фильтр `market` исключает пару с той же идентичностью и VLD; в этом наборе
все 318 настоящих пар имеют разные VLD. Пороги отказа не применялись и не
подбирались: на внешнем наборе нет запросов без пары, поэтому F1/TNR отказа
здесь не оцениваются.

KR зависит от состава query и gallery. Его ухудшение на этом небольшом
аэросъёмочном наборе показывает границу переноса выбранных на других данных
параметров, но не опровергает измеренное улучшение KR на сплите ЛЦТ. Сравнивать
`0,4903` с локальным `0,7741` как две оценки одной генеральной совокупности
нельзя: домен, размер галереи и число положительных кадров на ID различаются.
