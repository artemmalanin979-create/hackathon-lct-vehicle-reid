# Отчёт job_10 — каркас сдаваемого сервиса Vehicle ReID

Дата: 2026-09-15. Результат — в `service/` (переносится в репозиторий как есть).
Ход работы по шагам — в `journal.md`; свидетельства прогонов — в `work/`.

## 1. Как устроен сервис и почему так

Три компонента, как требует ТЗ (разд. 6): инференс, хранилище, клиент — раздельно.

```
service/
├── app/core/          ядро: препроцессинг, ONNX-модель, косинусы, запись файлов
│                      (семантика 1:1 с бейзлайном и измерительным контуром)
├── app/batch.py       пакетный прогон: CSV+изображения → 3 сдаваемых файла;
│                      зависит только от numpy/pillow/onnxruntime
├── app/api/           FastAPI (5 методов, OpenAPI) + обёртка Qdrant
├── app/load_gallery.py отдельный воспроизводимый шаг загрузки галереи
├── app/static/        тонкий клиент (браузер, POST /api/search) и офлайн Swagger UI
├── model/             веса OSNet-AIN x1.0 ONNX (8,4 МБ) + fetch_model.sh
├── Dockerfile         веса COPY внутрь образа, sha256 проверяется при сборке
└── docker-compose.yml api + qdrant одной командой; loader — по профилю tools
```

Ключевые решения:

- **Ядро отделено от API и СУБД.** `app/batch.py` не импортирует ни FastAPI, ни
  Qdrant — пакетный прогон на закрытом тесте не зависит от поднятого хранилища
  (проверено: оба контрольных прогона шли без Qdrant вовсе, один — с
  `--network none`, где никакая СУБД недостижима физически).
- **Все пути — аргументы.** В коде нет ни одного зашитого пути или имени файла;
  порог, модель и адрес Qdrant переопределяются флагами/переменными окружения,
  разумные значения по умолчанию зафиксированы в `app/core/config.py` с
  указанием происхождения каждого числа.
- **Численная эквивалентность бейзлайну** — осознанная цель: те же формулы
  (float64, максабс-нормировка, clip, стабильная сортировка), тот же формат
  записи (`csv.writer`, confidence `%.6f`), полный порог
  `0.34921352213815304` без округления. Поэтому сверка получилась побайтовой
  (см. § 3).
- **Хранилище — Qdrant** (свободная, один контейнер, косинусная метрика);
  поиск exact, чтобы ответы API совпадали с пакетным прогоном; ANN — задача
  масштабирования, не этапа.
- **API — минимум методов**: `health`, `version` (служебные из ТЗ),
  `embed` (вектор из кадра+bbox), `search` (кандидаты с уверенностью либо
  **честный пустой ответ**), `search/vector` (то же по готовому вектору).
  Все описаны в OpenAPI; Swagger UI работает офлайн (локальные js/css, без CDN).
- Единственное сознательное отличие от бейзлайна: поиск файла кадра перебирает
  расширения `.jpg/.jpeg/.png` (ТЗ допускает PNG). На выданных данных не влияет:
  все 11 416 файлов — `.jpg`, оно пробуется первым; побайтовое совпадение
  выходов это подтверждает (§ 3).

## 2. Точные команды запуска

Весь стек одной командой (из каталога `service/`):

```bash
docker compose up --build -d
# тонкий клиент: http://localhost:8000/   документация: http://localhost:8000/docs
```

Загрузка галереи в хранилище — отдельный воспроизводимый шаг:

```bash
DATA_DIR=/абсолютный/путь/к/data docker compose run --rm loader
```

Пакетный прогон на произвольном тестовом наборе (хранилище и сеть не нужны):

```bash
docker build -t vehicle-reid-service .
docker run --rm --network none \
  -v /путь/к/набору:/data:ro -v /путь/к/выводу:/out \
  vehicle-reid-service \
  python -m app.batch --images-dir /data/images \
      --query /data/test_query.csv --gallery /data/test_gallery.csv --out-dir /out
```

Проверялось на машине через podman 5.8.2 / podman-compose 1.6.0 (формат тот же);
два локальных нюанса задокументированы в README: `podman-compose` требует явного
`--profile tools` для loader, при SELinux каталогу данных нужна метка (`:z` или
`chcon -Rt container_file_t`). Для docker у жюри оба нюанса не существуют.

## 4. Доказательство работы без сети

Что именно запускалось и что вышло:

1. Образ собран **с нуля, без кеша**:
   `podman build --no-cache -t vehicle-reid-service ./service` — успех; на шаге
   сборки печатается «веса модели в образе, sha256 OK» (проверка sha256 весов
   зашита в Dockerfile).
2. Негативный контроль, что флаг действительно отрезает сеть:
   `podman run --rm --network none vehicle-reid-service python -c "urlopen('https://example.com')"`
   → `URLError: Temporary failure in name resolution`.
3. Пакетный прогон в контейнере **с отключённой сетью**, на переименованной копии:

   ```bash
   podman run --rm --network none \
     -v …/work/altcopy/zakrytyi-nabor-42:/data:ro,z -v …/work/container_out:/out:z \
     vehicle-reid-service python -m app.batch --images-dir /data/kadry \
       --query /data/zaprosy_zh.csv --gallery /data/galereya_zh.csv --out-dir /out
   ```

   → успех за 79 с: `{"queries": 1110, "gallery": 750, "embeddings_shape": [1860, 512],
   "queries_refused": 3, …}` (полный вывод — `work/container_out/run_info.json`).
4. Контейнерные файлы против хостовых на том же входе: `submission.csv` и
   `candidates.csv` **побайтово идентичны**, `embeddings.npy` **бит-в-бит** —
   несмотря на другой python (3.13.15 в образе против 3.13.13 в venv) и другую
   утилизацию потоков (79 с против 172 с).

Итого замкнута цепочка равенств:
**артефакты бейзлайна == host_run == переименованная копия (с точностью до имён) == контейнер офлайн**.

## 6. Что не сделано и почему

- **Оформление тонкого клиента** — по заданию: рабочая страница есть
  (кадр + bbox → кандидаты/отказ через `/api/search`), красота — отдельная задача.
- **Калибровка порога отказа** — порог взят из артефактов бейзлайна
  (argmax F1 на валидации, F1=0.867 при TNR=0.144) и заявлен черновым в README;
  подбор баланса F1/TNR — отдельная задача моделирования, не каркаса.
- **ANN-режим Qdrant и масштабирование галереи** — поиск сейчас exact: галерея
  мала, а ответы обязаны совпадать с пакетным прогоном; ANN включается
  конфигурацией коллекции, когда галерея вырастет.
- **Проверка на реальном docker** — на машине его нет; проверено podman 5.8.2 +
  podman-compose 1.6.0, совместимыми по формату файлов. Файлы называются
  `Dockerfile`/`docker-compose.yml`, синтаксис стандартный (compose v3-стиль,
  профили, именованный том) — исполнимо docker compose v2 у жюри.
- **GPU** — не требуется: CPU-инференс 1860 кропов занимает 79 с в контейнере;
  для закрытого теста этого достаточно с большим запасом.
