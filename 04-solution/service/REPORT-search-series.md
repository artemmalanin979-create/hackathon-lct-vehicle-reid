# Серия снимков поиска: одиннадцать машин, как есть

Снято на живом стеке (`podman-compose`: Qdrant + API + загрузчик галереи), без правок
кода, стиля, порогов и данных. Всё, что на снимках, пришло из сервиса: подмены ответов,
в отличие от прошлого прогона, здесь нет нигде.

- Интерфейс: 1440 px, DPR 2, полный экран страницы. Светлая тема — для показа, три кадра
  продублированы в тёмной.
- Поиск: `POST /api/search`, шкала — косинусная близость, порог отказа
  **0.549595**, `top_k` = 10 (значения по умолчанию, ничего не трогалось).
- Галерея: **750 объектов из размеченного проверочного сплита**
  (`04-solution/split/files/val_gallery.csv`), запросы — оттуда же (`val_query.csv`).
  Штатная сборка грузит `data/test_gallery.csv` — это тест организатора **без**
  `vehicle_id`, по нему нельзя сказать, верен ответ или нет. Галерея заменена
  параметром загрузчика (`--gallery`), решение не менялось.
- Все числа под снимками сверены с живым сервисом (`verify_live.py`): 11 запросов,
  расхождений 0.

В каждом снимке раскрыт список «ниже порога», поэтому виден весь top-10, а не только
принятые кандидаты. «Верно» ниже означает совпадение `vehicle_id` запроса и объекта
галереи; отдельно помечено, с той же камеры кадр или с другой — вторая задача и есть
настоящая: связать два вида одной машины с разных точек.

## Что эта серия показывает про поведение сервиса

**Сервис уверенно узнаёт машину и не уверен, что это тот же кадр.** На всех 832 запросах
сплита, у которых в галерее есть пара, медиана близости к кадру **той же камеры** —
0.919, а к кадру **другой камеры** — 0.553 при пороге 0.549595. То есть настоящая
задача — кросс-камерная — решается ровно на границе принятия решения: **408 верных пар
из 832 (49 %) не проходят порог**, а **137 (16 %) вообще не попадают в top-10**. Снимки
01–03 и 10–11 показывают верхнюю часть этого разброса, 04–07 — нижнюю.

**Топ-1 почти всегда верный, и это мало что значит.** В выдаче интерфейса чужая машина
стоит первой лишь у 24 запросов из 832 — но первым идёт кадр с той же камеры, почти
дубль. Под протоколом оценки, где такой кадр исключается как служебный, ошибок топ-1
уже **307 из 832 (Rank-1 0.631)**. Снимок 04 — как это выглядит для оператора: верный
ответ третий, а второй вид той же машины — десятый и ниже порога.

**Предел признака внешности виден прямо в интерфейсе.** На 06 и 07 сервис ставит выше
верного второго ракурса чужие машины в такой же ливрее, и разбор объясняет почему:
вклад размазан по раскраске кузова, а не собран на приметах. Это те самые 28 взаимных
пар, на которые приходится 84 из 307 ошибок (27 %) и которых переранжирование не чинит.
Кадр 05 — тот же эффект в мягком виде: в ливрее приняты все 10 кандидатов подряд, и
восемь из десяти — чужие машины в такой же раскраске.

**Отказ работает и стоит недёшево.** 08 — честный отказ там, где пары нет: галерея
просмотрена целиком, лучшая близость 0.432, решение объяснено числами. 09 — тот же
отказ с запасом в 0.0029: порог решает третьим знаком, и на 06 из-за этого не прошёл
уже **верный** кандидат (0.5441 против 0.549595). Порог откалиброван, но серия
показывает, что цена ошибки калибровки — конкретные пропущенные совпадения, а не
абстрактный процент.

**Что сервис умеет хорошо.** Смена освещения и ракурса — не приговор: 10 связывает
ночной кадр с дневным на 0.8116, 11 связывает борт с фасом сверху на 0.6527. Оба
случая с большим отрывом от чужих. Значит информация в кадрах есть, и ломается именно
метрика близости — это согласуется с разбором ошибок, где голое переранжирование
поднимает Rank-1 на парах «ночь ↔ день» на +0.117.

## Как воспроизвести

```
# 1. стек (из 04-solution/service)
podman-compose up -d
# 2. галерея с разметкой вместо тестовой
podman run --rm --network service_default -e QDRANT_URL=http://qdrant:6333 \
  -v <repo>/data:/data:ro -v <каталог с val_gallery.csv>:/split:ro,z \
  localhost/vehicle-reid-service:latest \
  python -m app.load_gallery --images-dir /data/images --gallery /split/val_gallery.csv
# 3. выбор случаев и съёмка
python3 pick.py          # top-10 по косинусу для всех 1110 запросов -> picks_all.json
python3 twins.py         # взаимные двойники (307 ошибок / 28 пар / 84 — сходится с разбором)
python3 shortlist.py     # короткие списки по рубрикам
python3 verify_live.py   # сверка выбранных запросов с живым сервисом
python3 shoot_series.py shots
```

Ход работы — `journal.md`. Контактные листы, по которым выбирались машины, — `sel/`.
