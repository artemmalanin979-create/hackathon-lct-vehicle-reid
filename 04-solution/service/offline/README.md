# Базовые образы для сборки без интернета

ТЗ п. 8 требует, чтобы инференс работал без доступа в сеть, а всё необходимое
поставлялось в составе решения. Колёса Python лежат в `../wheels/`, веса — в `../model/`.
Здесь — два базовых образа, которые иначе пришлось бы тянуть из реестра: на них ссылаются
`Dockerfile` и `docker-compose.yml`.

| Файл | Образ | Размер | Digest образа |
|---|---|---:|---|
| `python-3.13-slim.tar.gz` | `python:3.13-slim` — базовый образ сервиса | 45,6 МБ | `sha256:9d2e5553305c7c7b0097999bb17187c69b921ccd6bc9d40e4bb5ebe652c00285` |
| `qdrant-v1.15.5.tar.gz` | `qdrant/qdrant:v1.15.5` — векторная база | 65,4 МБ | `sha256:0fb8897412abc81d1c0430a899b9a81eb8328aa634e7242d1bc804c1fe8fe863` |

Каждый образ — в своём архиве: так исключена ошибка многообразного архива (см. ниже) и
соблюдён лимит GitHub в 100 МБ на файл.

## Загрузка

```bash
sha256sum -c SHA256SUMS
docker load -i python-3.13-slim.tar.gz     # или podman load -i …
docker load -i qdrant-v1.15.5.tar.gz
docker images | grep -E 'python|qdrant'    # сверить идентификаторы и размеры
```

Должно получиться ровно это:

```
python       3.13-slim   51cce855bb6e   130 MB
qdrant       v1.15.5     0ad2e23181e5   181 MB
```

Проверено загрузкой в **отдельное хранилище** (`podman --root /tmp/proverka --runroot
/tmp/proverka-run load`), чтобы проверка не могла испортить рабочее: оба образа встают с
правильными идентификаторами и размерами.

## Сборка без обращения к реестру

```bash
podman build --pull=never --network none -t vehicle-reid-service ..
```

`--network none` изолирует только шаги `RUN`: базовый образ тянется **до** них, поэтому
нужен запрет вытягивания. `--pull=never` — флаг Podman. У Docker `--pull` булев, и
`--pull=false` не запрещает дотянуть отсутствующий базовый образ, поэтому там изоляцию
обеспечивают отключением сети у демона либо предварительной загрузкой образов, что и
делают приведённые выше команды.

## Как пересобрать архивы

```bash
docker save python:3.13-slim   | gzip -9 > python-3.13-slim.tar.gz
docker save qdrant/qdrant:v1.15.5 | gzip -9 > qdrant-v1.15.5.tar.gz
sha256sum python-3.13-slim.tar.gz qdrant-v1.15.5.tar.gz > SHA256SUMS
```

**Ловушка, на которую мы наступили 21.09.** Если сохранять два образа одной командой,
`podman save` без `--multi-image-archive` молча кладёт в архив **только первый** и
навешивает на него оба тега. Ошибки нет, код возврата 0, а `podman load` такого архива
печатает обе строки «Loaded image» — и при этом перепривязывает тег Qdrant к образу
Python, после чего сломано уже локальное хранилище (лечится
`podman tag 0ad2e23181e5 docker.io/qdrant/qdrant:v1.15.5`, если настоящий образ ещё не
собран мусорщиком).

Признак был виден по размеру: битый архив весил 44 МБ вместо 111 — ровно на объём
отсутствовавшего Qdrant меньше. Поэтому здесь каждый образ лежит отдельно, а проверять
надо не тем, что `load` отработал, а сверкой идентификаторов и размеров после загрузки.

Оба образа распространяются свободно: `python:3.13-slim` — официальный образ Docker на
Debian с Python под лицензией PSF, `qdrant/qdrant` — Apache 2.0.
