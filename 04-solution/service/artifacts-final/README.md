# Выпуск файлов для тестового набора

Комплект от **29.09.2026** получен одним офлайн-прогоном `app.batch` из
изображений и CSV, выданных организаторами. В Git включены все четыре выходных
файла и [manifest.json](manifest.json); исходные изображения передаются через
личный кабинет задачи. Меток `vehicle_id` и `camera_id` для test нет, поэтому
качество на закрытом тесте здесь не заявляется.

| Файл | Содержимое |
|---|---|
| [`submission.csv`](submission.csv) | 1110 строк **без заголовка**: ID запроса и 10 различных ID галереи, по убыванию независимого top-50 KR |
| [`embeddings.npy`](embeddings.npy) | `float32`, форма `(1860, 512)`: 1110 query, затем 750 gallery в порядке исходных CSV |
| [`candidates.csv`](candidates.csv) | Заголовок `query_id,gallery_id,confidence` и 2664 принятые пары по косинусу; у 48 запросов нет строк — отказ |
| [`run_info.json`](run_info.json) | Модель, SHA весов, оба режима оценок, порог, размеры, версии и время прогона |

`submission.csv` использует **d1_j48 + k-reciprocal (k1=6, k2=3, λ=0,3)**:
для каждого запроса отдельно берутся его cosine top-50 из статичной галереи,
затем обрабатывается только группа «текущий query + эти 50 объектов». Другие
query не служат контекстом. Остальные объекты идут ниже top-50 в порядке cosine.
`candidates.csv` использует **cosine**, порог
`0.5141976914190476`, сравнение до округления confidence до шести знаков.
Переранжирование не меняет признаки. HTTP API тоже ищет по cosine, поэтому
его порядок может отличаться от `submission.csv`.

## Воспроизведение

В [manifest.json](manifest.json) закреплены исходный commit пакетного кода
`640ced67efbd9f23527d5f955c59b2258f97d8fa`, image ID
`150a6853fa262b20891e1dbe5184a3d8812e970eac72bf414496736f1405b8bb`,
SHA-256 test-CSV, manifest изображений, параметры запуска и отпечатки выходов.
Для проверки поставленных файлов:

```bash
cd 04-solution/service/artifacts-final
sha256sum -c SHA256SUMS
```

Для пересчёта из разрешённых исходных данных после подготовки образа и каталога
`data/` выполните из корня репозитория:

```bash
mkdir -p outputs/recheck
docker run --rm --network none --cpus 2 --memory 4g \
  -e OPENBLAS_NUM_THREADS=1 -e OMP_NUM_THREADS=1 \
  -v "$PWD/data:/data:ro" -v "$PWD/outputs/recheck:/out" \
  vehicle-reid-service python -B -m app.batch \
  --images-dir /data/images --query /data/test_query.csv \
  --gallery /data/test_gallery.csv --out-dir /out --threads 2 --batch 32
```

На SELinux добавьте `--security-opt label=disable` либо корректную метку
монтирования. Команда
производит согласованные файлы; полный SHA-256 может различаться на другой
платформе или при другой раскладке потоков из-за последних битов инференса.
Проверяйте формат, порядок строк, модель и метрики на размеченной validation;
не сравнивайте только хеш с артефактом другой машины. Подробный протокол —
[§7 SOLUTION.md](../../../SOLUTION.md#reproduction).

Зафиксированный прогон: **1110 query × 750 gallery**, 1062 запросов с хотя бы
одной принятой косинусной парой, 48 отказов. В ограниченном контейнере
`--cpus 2`, `--threads 2` извлечение векторов заняло **263,424 с**, ранжирование
**9,384 с**, весь batch **273,259 с**. Это проверка воспроизведения, не замер
показателя «кадр → вектор» на GPU организатора и не оценка качества test.

Предыдущий выпуск от 21.09 объединял все query перед KR и применял к
`candidates.csv` порог другой шкалы. Он остался в истории Git для анализа,
но текущими файлами сдачи являются только перечисленные выше.
