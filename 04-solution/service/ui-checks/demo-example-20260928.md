# Проверка демонстрационных кадров, 28.09.2026

Первый прежний пример (`a4f2a13bd2b54360a921c8ef7366e535`) при реальном
`POST /api/search` ставил первым `db620271348d404a9a0b978d96c63f29` с
cosine 0,990309. ID и SHA-256 JPEG различаются, но полные кадры визуально
почти совпадают: одна сцена с почти той же рамкой. Это плохая демонстрация
поиска по разным снимкам; подмена результатов или изменение индекса не нужны.

В каталоге `GET /api/demo` оставлены один положительный пример и отдельный
пример отказа. Положительный query взят из исходного `test_query.csv`.
Проверка проведена на неизменной d1_j48 и галерее из 750 объектов:

| Пример | Query ID и bbox | Первый gallery ID | Cosine | Порог |
|---|---|---|---:|---:|
| Автомобиль с другого ракурса | `e03daa7cd69147cf9ffcfe59b6f1ff74`, `734,341,608,551` | `e429a2e164a24919a12edcc8d4ea8f09` | 0,678976 | 0,5141976914190476 |

Выбранная рамка покрывает весь автомобиль. Первый и второй кандидаты сняты
с других точек: среди двух видимых лидеров нет почти копии query.
Сравнение полных кадров и кропов сделано вручную независимым проверяющим.
Хеши JPEG пары: `d721a626545ba5ca289afe8d7ef7feea9e410fb46ef312b90c4aec7acac09fda`
и `aa331fd494f9d30ffd48bdeea51d2f7b9d22636a89087b1af3527b7411444e9e`.

Кандидат `285ed58a8d154d748bba60ef4ef0123d` был проверен, но отвергнут
для публичного каталога: его CSV bbox срезает переднюю половину автомобиля,
а среди видимых результатов есть соседний кадр query. Исходные CSV/галерея
от этого не меняются.

Команда проверки для каждого кадра: `curl -F file=@<JPEG> -F x=<x> -F y=<y>
-F w=<w> -F h=<h> http://127.0.0.1:18071/api/search`. Ответы сохранены в
локальных `outputs/continuation-20260925/demo-candidate-20260928/*.json`;
первичные изображения поставляются разрешённым способом отдельно от Git.
Закрытый test не содержит меток личности и камеры: этот пример показывает
работу ранжирования и отличающиеся снимки, но не доказывает межкамерную
верность найденной пары. Модель, порог, галерея и пакетные артефакты не менялись.
