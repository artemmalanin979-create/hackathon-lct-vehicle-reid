**Вердикт: конфигурацию не меняем. Ни одно из шести сочетаний не подтвердило прирост KR mAP; дополнительный CPU-инференс имеет измеримую стоимость.**

Максимальная наблюдаемая KR mAP у **ABD: 0.777873655**, Rank-1 0.739182692. Относительно d1_j48: ΔmAP=+0.003782 (0.282σ), CI95 [-0.003303; +0.010959], p=0.309423, p_Holm=1.000000. Одновременный семейный CI95 [-0.005819; +0.013439] включает ноль. Это колебание в пределах неопределённости, а не доказанный прирост.

Цена этого сочетания: **662.0 мс/кадр** против **372.5 мс** у контроля в том же прогоне (+77.7%). Исторический контроль job_68 — 413,5 мс.

## 2. Зафиксированный протокол и все сочетания

Рассмотрены все расширения обязательной базы A+B одной или двумя из C/D/E: **ABC, ABD, ABE, ABCD, ABCE, ABDE**. Это три трёхветочных и три четырёхветочных сочетания; контроль AB не входит в число шести проверяемых гипотез.

Для каждого сочетания: float64 L2 каждой ветви → равновесное среднее с L2 → собственный whitening ρ=0,5 → L2 → cosine или KR (k1=6, k2=3, λ=0,3). В коде сохранён порядок исходного d1_j48: L2 суммы вместо L2 среднего; общий множитель сокращается. Ни веса ветвей, ни параметры не подбирались.

Каждый whitening обучен заново только на **7248 own train_fit / 1171 ID / 13485 положительных межкамерных пар**, без внешних наборов и валидации. Пары определены как same vehicle_id и different camera_id; covariance shrinkage и Cholesky взяты из штатного `lib45.learn_lw`. Матрицы и статистика сохранены в `out/*_whitening.*`.

Метрики получены импортом неизменённого `04-solution/eval/reid_metrics.py`: **market + presence**, 1110 query / 750 gallery, усреднение ранговых метрик по **832 known**. ## 3. Парный bootstrap и множественные сравнения

**4000 ресэмплов, seed=20260921, σ=0,0134.** Одни и те же индексы ресэмплов использованы для всех сочетаний; внутри каждого запроса сохраняется пара кандидат/контроль. Первичная семья — шесть сравнений KR mAP. Двустороннее сырое p рассчитано по хвостам bootstrap-распределения с add-one поправкой, как в job_68; затем применён Holm step-down.

Обычный CI95 — percentile [2,5%; 97,5%]. Для защиты после множественных сравнений дополнительно даны консервативные интервалы Bonferroni с **номинальным семейным покрытием 95%**: каждый интервал 99,1667%, квантили [0,41667%; 99,58333%]. Это **не интервалы Холма**; Holm применяется к p. Выбран более консервативный явный критерий: Δ>0, p_Holm<0,05 и нижняя граница семейного CI95>0. Порядок, N и критерий записаны в journal.md до просмотра новых результатов.

**Ни одно сочетание не прошло критерий подтверждённого прироста основной KR mAP.** σ — заданный масштаб сравнения, а не оценка стандартной ошибки парной дельты. Изменения меньше σ без значимости не засчитываются. Дополнительные cosine/Rank-1 bootstrap сохранены как диагностические, но не использованы для изменения основного критерия. ## 4. Цена одного кадра на CPU

worker-vm / ThinkPad P50, CPUExecutionProvider, **batch 1, intra-op 2, inter-op 1**, 50 тех же объектов и пять прогревочных объектов на сочетание, как в job_68. Все модели каждой конфигурации выполняются последовательно; включены forward, L2, слияние и whitening. Декодирование JPEG, crop/resize, создание сессий, поиск и KR исключены.

Порядок семи конфигураций перемешан для каждого объекта фиксированным seed. Неактивным ORT-сессиям отключён spinning, чтобы лишние пулы не занимали CPU; это отличие от старого замера явно зафиксировано. Сравнивать цену следует прежде всего с одновременным контролем AB; 413,5 мс из job_68 приведены как исторический ориентир. Извлечение train_fit завершилось до начала замера. ## 5. Абляция номера и сохранность конфигурации

Абляция новой конфигурации по условию брифа обязательна при подтверждённом приросте. **Для основного сдаваемого режима KR условие не выполнено**, поэтому новая абляция не запускалась; результаты job_68 не переносятся на новые сочетания и не объявляются их проверкой.

Сдаваемые модели, whitening, параметры и пороги не менялись. Коммитов и push не было. Численные расчёты и ONNX-инференс выполнялись на worker-vm, по два CPU-потока на процесс. Локально выполнены чтение файлов, перенос результатов и сборка отчёта.
