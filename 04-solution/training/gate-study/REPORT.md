# job_56 / доведение job_58: гейт между моделями — однократный замер на val и вердикт

Дата: 2026-09-20. Узел: worker-vm, `~/lct-reid/jobs/job_56/`.

## Постановка

Правила переключения/объединения моделей G1–G4 заморожены на train_fit (s03). Задача — по одному
измерению каждого на val против чемпиона d1_j48 (val mAP 0,7741, бутстрэп-SD 0,0134; 832 known-запроса,
парный бутстрэп B=4000, seed 20260916, канон job_42/45). Контур метрик — `04-solution/eval/reid_metrics.py`,
KR (6,3,0,3) канонический.

## Метод и правка скрипта

`scripts/s04_val_measure.py` проверен: правила читает замороженные (`out/s03_gate_G*.json`), векторы —
валидные (`load_val()` osnet/ainv2, job_48 val_j48, lw-матрицы с train_fit). Исправлен один баг перед
запуском: gap-признак в s01 сохранён по всем 1110 вал-запросам, а per-query AP — по 832 known; в G1
добавлена индексация `[known_idx]` (без неё падение по broadcasting). Концепция не менялась.

## Абляция номера

Не выполнялась — основания нет: ни одно правило не превзошло 0,7741 (условие было «значимо выше»).

## Вердикт

Надёжного способа поднять val выше 0,7741 этим путём — обучением гейтов/перевзвешивания на train_fit —
нет: единственные отличные от нуля эффекты на val отрицательны (G2 −0,0139, G4 −0,0041, оба p ≤ 0,001),
а «пустые» правила (G1, G3) не дают ничего. Потолок идеального переключения d1_j48↔d1_3 (0,7825) и
oracle по 6 моделям (0,8286) обученными на train_fit правилами недостижимы; отрицательный результат —
окончательный ответ по этому направлению. Оставляем чистый d1_j48.
