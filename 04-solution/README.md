## Действующий режим

Признак **d1_j48**: OSNet-AIN (OMZ) и дообученная нами combined_v1 получают
одинаковый кроп; каждый вектор нормируется, затем среднее нормируется,
пропускается через whitening (ρ=0,5) и снова нормируется. Получается 512 чисел.
`submission.csv` ранжирует каждый запрос независимо: cosine top-50 статичной
галереи → k-reciprocal (k1=6, k2=3, λ=0,3). `candidates.csv` и HTTP API
используют косинус с порогом 0,5141976914190476. Другие test-query не
используются для ответа на текущий запрос.

| Локальная validation 1110 query × 750 gallery | mAP@10 по `submission.csv` | Rank-1 | Rank-5 |
|---|---:|---:|---:|
| Независимый top-50 KR, сдаваемый | **0,7411030506** | **0,7079326923** | 0,8605769231 |
| Только cosine | 0,7242262382 | 0,6850961538 | **0,8822115385** |

Числа получены опубликованным организаторами `evaluate.py`: в mAP входят 832
запроса с допустимой межкамерной парой, 278 запросов без пары оцениваются
через отказ. Для текущих косинусных `candidates.csv` официальный F1 равен
**0,9391812865**, TNR — **0,7302158273** на том же сплите. Он уже много
раз использовался при разработке; скрытый тест без меток нами не оценивался.
Подробный протокол и SHA оценщика — в [§6–7 SOLUTION.md](../SOLUTION.md#validation-metrics).

Ранее общий KR объединял **все запросы и галерею** и давал full-ranking mAP
0,7740915539 и локальное mAP@10 0,7684546226. После уточнения организаторов
такой режим не используется в сдаче: каждый test-query должен обрабатываться
независимо. Эти числа и первоначальная калибровка KR сохранены в
[`training/combined/`](training/combined/) как история исследований, а не как
результат действующего `submission.csv`.

Отдельный обученный image encoder оказался быстрее в границе «готовый тензор
→ признак», но по тому же официальному top-50 протоколу дал mAP@10
**0,2979721523** против **0,7411030506** у d1_j48. Он не заменяет релиз;
условия обучения, скорости и точности — в
[отчёте эксперимента](training/owncore-distill-20260926/REPORT.md).

## Что сдаётся

`app.batch` создаёт `submission.csv` **без заголовка** (десять ID на запрос
при gallery ≥ 10), `embeddings.npy` в порядке query → gallery и
`candidates.csv` **с заголовком**. Отказ — отсутствие строк запроса в
`candidates.csv`. Все три результата строятся из одних эмбеддингов одного
прогона. [Состав и SHA-256 выпуска](service/artifacts-final/README.md) и
[форматы с известными ограничениями](../SOLUTION.md#submission-format) доступны
отдельно. Исходные изображения организатора не включены в Git и выдаются через
личный кабинет задачи.

## Исследовательский контроль

Для первого OSNet без дообучения проверялись случайные и идеальные векторы:
ожидаемые/полученные mAP случайной выдачи — 0,0103/0,0099, идеальной — 1,0/1,0.
Без исключения пар того же автомобиля и той же камеры исходный OSNet давал
0,812 mAP и 0,971 Rank-1; с исключением Rank-1 был 0,631.
[Сырые результаты](baseline/out/metrics_summary.json) сохраняют этот
исторический контроль. Он не описывает качество текущей d1_j48.
