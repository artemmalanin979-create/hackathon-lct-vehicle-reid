## 2. Находки (по убыванию тяжести)

### Н-1. SOLUTION.md описывает сборку, которой больше нет: про `wheels/` в нём нет ни слова

`Dockerfile` собирается **офлайн по умолчанию** (`ARG PIP_SOURCE=offline`, `pip install --no-index
--find-links=/wheels`). При этом:

- §3 шаг 3: «**Эта сборка требует интернет:** Dockerfile получает Python-образ и устанавливает пакеты
  из PyPI»;
- §11: «Сохранённый образ работает офлайн, **сборка с PyPI — нет**»;
- `04-solution/service/README.md` (стр. 331–341): «Сборка образа требует сети… Если нужна и
  офлайн-сборка, зависимости надо везти колёсами внутри репозитория — **сейчас это не сделано**».

Слова `wheels`, «колёса», `PIP_SOURCE` в `SOLUTION.md` не встречаются ни разу; запасной путь
`--build-arg PIP_SOURCE=network` тоже не документирован. Актуален только `wheels/README.md` — файл,
до которого жюри доходит, только если само заглянет в каталог.

**Почему это тяжелее, чем опечатка.** Каталог колёс был добавлен именно как страховка под разд. 9 ТЗ
(сборка в изолированной среде). Жюри, читающее сдаваемый документ, об этой страховке не узнает: оно
прочтёт «нужен интернет», а в README решения — ещё и прямое «офлайн-сборка не сделана». Лучшее, что
есть в поставке, документацией отрицается.

### Н-2. Подмена под SELinux нужна четырём командам, а описана у одной — и падение стоит 5,5 минут

Сноска про `--security-opt label=disable` есть только в §4 (пакетный прогон). Фактически без неё
падают **все** команды с bind-mount: пакетный прогон (`/out`), T (`/repo`), R (`/repo`+`/data`+`/out`),
калибровка. Хуже другого: пакетный прогон пишет файлы **в самом конце**, поэтому
`PermissionError: [Errno 13] Permission denied: '/out/embeddings.npy'` приходит через 5 м 33 с
после старта — весь инференс выполнен и выброшен. Команда T падает и вовсе с сообщением
не по делу: `ModuleNotFoundError: No module named 'test_protocols'` (файл на месте, читать каталог
не дали).

Это специфика podman на SELinux-хосте, у жюри с Docker её может не быть — но подмена сделана
несимметрично, и по документации нельзя понять, что тот же флаг нужен и остальным трём командам.

### Н-3. Титульный README репозитория даёт устаревшие F1/TNR для сдаваемого режима

`README.md`, стр. 135: «Режим отказа: F1 / TNR — 0,733 / **0,698**». Это косинусная ветвь. Режим по
умолчанию (переранжирование, `t_rr`) даёт **0,806 / 0,777**, что и заявлено в §6 `SOLUTION.md` и
подтверждено прогоном. mAP/Rank-1 в README (0,694 / 0,663) при этом уже новые — то есть внутри
одной таблицы соседствуют числа двух разных конфигураций. README — первый файл, который открывает
проверяющий.

### Н-4. Слой `COPY wheels/` остаётся в образе: +59,2 МБ и неверные размеры архива в §4

```
COPY wheels/ /wheels/          ← отдельный слой, 59.2 MB (podman history)
RUN … pip install … && rm -rf /wheels   ← удаление в СЛЕДУЮЩЕМ слое, вес не возвращается
```

Следствие — задокументированные в §4 размеры офлайн-архива не воспроизводятся:

| Что | §4 | Факт | Разница |
|---|---:|---:|---:|
| `podman save --multi-image-archive` | 537 070 592 | 596 321 792 | +59 251 200 |
| `podman save` без флага | 355 952 640 | 415 203 840 | +59 251 200 |

Разница в обоих случаях **ровно** размер слоя с колёсами. Само предупреждение §4 про
`--multi-image-archive` подтвердилось полностью: без флага в архиве один образ с двумя тегами,
с флагом — два.

### Н-5. `gallery_points` — ненадёжный признак готовности: том переживает всё

§4 предлагает судить о готовности по `storage.gallery_points` в `/api/health`. Том Qdrant именованный
(`qdrant_storage`), а имя проекта compose берётся из имени каталога (`service`) — то есть **одинаково
для рабочего дерева и для любого клона**. На этой машине том существовал с 10:04 от чужого прогона,
и `up` из чистого клона отдал `gallery_points=750` **до** того, как мой `loader` доработал.
Признак готовности, названный в документации достоверным, показывает прошлую загрузку.

Побочно: мой прогон из чистого клона по этой же причине **не проверил** старт с пустым хранилищем —
он переиспользовал контейнеры и том рабочего дерева.

### Н-6. Сводка, которую печатает команда R, относится не к сдаваемому режиму

Последняя строка R печатает `"F1": base["refusal"]["f1"]`, `"TNR": base["refusal"]["tnr"]` — это
**косинусная** ветвь при `t_cos`: 0,733 / 0,698. Заявленные в §6 и в брифе 0,806 / 0,777 относятся к
переранжированию и лежат глубже, в `metrics.json` → `rerank_refusal`. Человек, запустивший R и
сверивший её вывод с §6, увидит расхождение там, где его нет.

### Н-7. Офлайн-сборка прошла только потому, что базовый образ уже лежал локально

`podman build --network none` успешен, но `FROM python:3.13-slim` брался из локального хранилища
(образ появился при сборке с сетью шагом раньше). На машине, где этого образа нет, сборка с
отключённой сетью упадёт на первой строке Dockerfile. Ни `wheels/README.md`, ни `SOLUTION.md` не
говорят, что базовый образ надо вытянуть заранее (`docker compose pull qdrant` в §3 тянет только
Qdrant).

### Н-8. Команды §8 для исследовательских скриптов не запускаются ни в одном окружении из поставки

`python 04-solution/postproc/scripts/s09_timing.py` и `…/plate-ablation/scripts/eval_variants.py`
падают мгновенно: `ModuleNotFoundError: No module named 'onnxruntime'`. Исследовательская `.venv`
(§10) в git не входит, инструкции её создать в `SOLUTION.md` нет; в образе сервиса этих скриптов
тоже нет. `s04_grid.py` падает на разборе аргументов (ждёт пять, в таблице записан без единого).
Строки §8 честно помечены «не воспроизведено», но записаны в графе «как получить» как исполняемые
команды — проверяющий получает трейсбек вместо понятного «этот путь не восстанавливается».

### Н-9. Имя сдаваемого документа (уже признано в §12)

ТЗ требует `Readme.md`; документация решения называется `SOLUTION.md`, а `README.md` занят описанием
проекта. §12 это прямо оговаривает — упоминаю для полноты списка рисков, новой находкой не считаю.

## 5. Подмены Docker → Podman (каждое место)

| № | Где в документации | Написано | Выполнялось | Разница, значимая для жюри |

| П-4 | §4 | `docker save -o … образ1 образ2` | `podman save --multi-image-archive -o …` | **Задокументировано в §4** и подтверждено: без флага в архив попадает один образ |
