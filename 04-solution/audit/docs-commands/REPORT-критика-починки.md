# job_90 — независимая проверка починки job_89

**Вердикт: оставлять починку в main как есть — нет.** Численный конвейер и документированный успешный путь сохранены, но обнаружены две регрессии совместимости: потоковый CSV отвергается новой диагностикой, а запуск исследовательских скриптов через `python -m` сломан новым импортом. Кроме того, 8 из 18 мутаций пережили штатные тесты; за пределами авторского списка остались два неправильных округления.

Проверяется **55ae46a**, исходная версия — **3e2cc9a**. Исходный репозиторий не изменялся; исправлений, коммитов и push нет. Все тестовые изменения — в отдельных копиях. Тяжёлые прогоны выполнены на `worker-vm`, основной batch ограничен 2 CPU / 4 GiB, сеть контейнера отключена. Результаты и воспроизводящие программы сохранены в этом каталоге.

## 1. Ложное срабатывание новой диагностики — подтверждено

**F1, приоритет P2. Читаемый CSV через pipe/FIFO перестал приниматься.**

В Bash допустимо передать `--query <(cat query.csv)`. Старый `read_rows` открывает `/dev/fd/63` и обрабатывает поток. Новая `require_files` в [input_checks.py:30](/home/artem/projects/hackathon-lct-vehicle-reid/04-solution/service/app/input_checks.py:30) требует `Path.is_file()`: для pipe это `False`, хотя он читаем. Результат — неверное «Нет файла» и exit 2.

Измерено настоящим `app.batch` с обеими ONNX-моделями и whitening: два запроса и десять элементов галереи взяты из настоящих validation-CSV; исходные изображения скопированы из набора организатора. До правки exit **0**, созданы три результата; после — exit **2**, вычисления не начались. Обычный CSV с теми же байтами обрабатывается обеими версиями. Это не проверка с заглушкой инференса.

Минимальное воспроизведение в окружении с зависимостями и штатными весами:

```bash
cd 04-solution/service
python -B -m app.batch --threads 1 --no-rerank \
  --query <(cat /data/query.csv) --gallery /data/gallery.csv \
  --images-dir /data/images --out-dir /out
```

Доказательства: [программа](scripts/path_cases.py), [результаты сценариев](evidence/paths/results.json), [до](evidence/paths/csv-process-substitution/full_before.log), [после](evidence/paths/csv-process-substitution/full_after.log).

Просто заменить `is_file()` на `exists()` недостаточно: `require_dataset` затем читает весь CSV для проверки, а основной загрузчик открывает его ещё раз. Одноразовый поток нужно учитывать на уровне чтения входа. Это вывод из кода; отдельный такой патч не вносился.

## 9. Границы вывода и состояние рабочего места

Не обнаружено изменения весов, формул, параметров KR, порядка embeddings или ранговых результатов на полных данных. Документированный прямой путь запуска прошёл. Найденные F1/F2 касаются прежде работавших вариантов подачи данных/запуска; F1 непосредственно вызван новой проверкой входов.

Штатные проверки с полностью отсутствующими входами недостаточны: они проходят и тогда, когда удалены отдельные обязательные проверки. До принятия починки без оговорок нужно закрыть подтверждённые регрессии и добавить различающие сценарии для выживших мутаций. Конкретное решение и любые правки остаются координатору.

Rerank-пара совпадала уже в обоих вариантах.
