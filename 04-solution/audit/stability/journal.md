## Контрольная точка и фиксированный протокол

- `worker-vm` доступен. Код метрик находится в `~/lct-reid/repo/04-solution/eval/reid_metrics.py`, данные — в указанных заданиях.
- `checkpoint.py` заново выполнил KR(6,3,0.3) и штатную оценку для сохранённых AB-векторов. В 17:21 UTC получено точное совпадение обеих контрольных метрик (проверка `float.hex`) и побитовое совпадение всех AP/Rank-1 с `job_48`.
- До получения статистики фиксируется основное семейство: семь готовых whitening-сочетаний `AB, ABC, ABD, ABE, ABCD, ABCE, ABDE` и пять одиночных ветвей `A, B, C, D, E`; каждое с cosine и с уже используемым KR(6,3,0.3). Всего 24 варианта, новых параметров и обучения нет. Отдельно будет показано семейство семи сочетаний с KR.
- A = OMZ @208, B = job_48 @208, C = обученная job_68 @256, D = OMZ @256, E = прежняя combined_v1 @256. База — A с KR, без whitening; ожидается `0.6936584724586873`.
- 200 seed генерируются однократно `default_rng(20260921)`, для каждого seed переставляются отсортированные known `vehicle_id`; одна половина получает floor(N/2) машин, другая остальные. Количество запросов может различаться. Число групп, seed, ID машин и индексы запросов будут сохранены.
- В основном анализе gallery и полный пул векторов query для трансдуктивного KR фиксированы. Делится доступ к query-меткам; AP и их агрегирование берутся непосредственно из штатного контура. Это условная устойчивость на данной галерее, не независимые новые галереи и не полное вложенное обучение.
- Для камер выполняется именно указанное в brief исключение каждой камеры по одной (leave-one-camera-out / jackknife, не bootstrap с возвращением). KR пересчитывается после удаления; известность запроса заново определяется по оставшейся gallery. Будут явно показаны потерянные positive-запросы и сравнение на одинаковом составе запросов.
