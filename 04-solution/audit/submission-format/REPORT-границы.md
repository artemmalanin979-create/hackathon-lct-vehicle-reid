В обычном неизменённом коде все четыре новых теста проходят вместе с прежними 21 сервисными. Для каждой мутации отдельно выполнены: прежние 21 тест на поломке, расширенные 25 на поломке и те же 25 после её снятия. Полный набор 115 не запускался на каждом мутанте и такое покрытие не заявляется.

Почему прежние проверки пропускали эти ошибки:

- **M06:** unit-проверка общего валидатора и API не доказывала его ранний вызов из batch. Новый тест использует валидные CSV/изображение, проверяет `nan`, `inf`, `-inf` в обеих шкалах, код 2, диагностику, отсутствие создания модели и out-dir. При M06 срабатывает именно запрет конструктора модели.
- **M13/M14:** прежние bbox у `(0,0)` отклонялись проверкой пересечения даже после поломки проверки размеров. Новые bbox находятся у `(8,8)` внутри кадра; `x+w` и `y+h` положительны даже при размере `-1`. Проверяются обе оси, нулевая и отрицательная площадь, и непосредственно crop, и настоящий preflight с CSV/строкой/ID/путём в ошибке. Отрицательная высота должна давать наш CropInputError, а не более поздний ValueError от PIL.
- **M21:** прежний тест проверял контекст ошибки `load_crop`, но не обработку этой ошибки в `batch.main`. Новый тест после настоящего успешного preflight повреждает файл при входе в конструктор модели. Чтение и ошибка PIL/CropInputError настоящие; заменены только модель и вычисление векторов. Проверены поздний сбой query и gallery, новый и уже заполненный out-dir, rc=2, диагностика без traceback и неизменность всех четырёх старых файлов. Для gallery подтверждено, что чтение query уже состоялось.

В [инвентаризации тестов](evidence/test-inventory.json) AST-сверкой подтверждено сохранение тел всех прежних 21 сервисного теста. ## Точный текст добавленного раздела SOLUTION.md

Раздел расположен в §5 сразу после правил сериализации, якорь `known-behavior-limits`.

```markdown
### Известные границы поведения

Эти ограничения относятся к `app.batch` текущего выпуска d1_j48. Они
подтверждены [аудитом формата](04-solution/audit/submission-format/REPORT.md)
и [проверкой исправлений F1/F5](04-solution/audit/submission-format/REPORT-критика-починки.md).
Ниже — оставленные границы, а не заявленные исправления.

- **F2 — галерея меньше десяти объектов.** При одном объекте заголовок
  `submission.csv` содержит 11 полей, строки — два; batch завершается с кодом 0.
  Вообще при `1 <= N_gallery < 10` пустые позиции не дополняются. Исправление
  отложено до согласования заполнителя с организатором: формат недостающих ID
  не определён. Для прямоугольного submission нужны минимум десять строк
  галереи; код 0 сам по себе не гарантирует эту схему.
- **F3 — пустая галерея.** При непустом query и `N_gallery = 0` batch
  завершается с кодом 1, новых файлов нет; продуктовый ответ «совпадений нет»
  не формируется. Пустой query также не поддержан. Обработка оставлена до
  согласования формата пустого комплекта. Перед запуском нужны непустые CSV;
  проверяйте код возврата, поскольку прежние файлы в `out-dir` могут остаться.
- **F4 — повторяющиеся `image_id`.** Разные bbox одного query имеют одинаковый
  ключ результата: join неоднозначен, отказ одного bbox может скрыться за
  принятым совпадением другого. Дубликаты gallery повторяют ID в топе и пары
  в `candidates.csv`. Исправление требует согласованного идентификатора
  объекта вместо одного ID кадра; схему выпуска не меняем. Для однозначной
  выдачи обеспечьте уникальность `image_id` отдельно в query и gallery до
  запуска: сам batch её не проверяет.
- **F6 — округление confidence.** Пара принимается по исходному `s >= t`,
  затем `s` записывается с шестью знаками. На границе записанное значение
  может оказаться ниже полного порога. Точность CSV оставлена прежней, чтобы
  сохранить формат выпуска и решение по неокруглённой оценке. Наличие пары
  в `candidates.csv` означает принятие; не фильтруйте её повторно по
  округлённому confidence.
- **F7 — больше десяти принятых пар.** `candidates.csv` содержит все пары,
  прошедшие порог; в аудите получено 15 на запрос. Усечение не добавлено:
  первичные требования задают десять только для `submission.csv`. Читатель
  `candidates.csv` должен поддерживать произвольное число принятых строк;
  для первых десяти используется `submission.csv` независимо от отказа.
- **Остаток F1 — отказ точной копии кадра.** На проверенном наборе 37 query
  и 37 gallery при штатном KR точная копия получает оценку около `0.44`
  и отклоняется порогом `0.5282812306342437`. Защита от NaN исправлена,
  этот дефект ранжирования остался. Исправление отложено до отдельной проверки
  алгоритма KR, калибровки и полного прогона. Наличие точной копии не
  гарантирует принятия; для малых наборов
  используйте рекомендацию по косинусному режиму в §2, без гарантии метрик
  большого сплита.
```
