## F1: исправленное вырождение и оставшийся неверный ответ

**Находка высокого приоритета: штатный batch отказывает точной копии кадра при обычном пороге.** Это остаточный дефект F1, **не новая регрессия** двух коммитов.

Условия: собственный набор [query](fixtures/formats/regular-query.csv) и [gallery](fixtures/formats/regular-gallery.csv) содержат одинаковые 37 строк; изображения — [fixtures/formats/images](fixtures/formats/images). `k1=6`, `k2=3`, lambda=0.3, threshold=`0.5282812306342437`, batch=32, ONNX threads=2, BLAS/OMP/MKL=1. Эмбеддинги соответствующих строк query/gallery побайтно равны. Тем не менее:

| Query index, с нуля | image_id, bbox `(0,0,128,96)` | Score собственной копии = best | Итог |
|---:|---|---:|---|
| 0 | rgb.jpg | 0.43999999999999984 | Отказ |
| 3 | progressive.jpg | 0.43999999999999984 | Отказ |
| 5 | exif_1.jpg | 0.43999999999999984 | Отказ |
| 12 | exif_8.jpg | 0.43999999999999984 | Отказ |

Это **не отказ preflight**: batch возвращает rc=0, пишет полный комплект и 4 ложных отказа в режиме поиска. Старый и новый код дают одинаковые файлы. Повтор нового кода снова дал те же четыре отказа и равные байты всех трёх файлов. [Построчная проверка self-match](results/degenerate/real-image-selfmatches.json), [живой повтор](results/selfmatch-repeat/analysis.json).

Готовая команда повторения на сохранённом worker-стенде:

```bash
bash scripts/replay_selfmatch.sh
```

Она запускает новый ограниченный контейнер, читает те же 37+37 изображений настоящими моделями и пишет отдельный каталог `scratch/selfmatch-replay`; ожидаемое `queries_refused=4`. [Сам скрипт](scripts/replay_selfmatch.sh) содержит все mounts и параметры.

Причина подтверждена трассировкой `rerank_distances`: для query 0 соседи QE `[0,21,22]` имеют k-reciprocal-наборы `[0]`, `[]`, `[]`. После усреднения сумма V становится **1/3**. V(query) и V(его точной копии) равны, но формула Jaccard даёт self-distance **0.8**, поэтому score около 0.44. Все максимумы столбцов положительны (min≈0.7183): новый guard `column_max == 0` не включается. [Значения промежуточных матриц](results/degenerate/selfmatch-trace.json), [скрипт трассировки](scripts/trace_selfmatch.py). Работа с пустыми взаимными окрестностями и ties остаётся отдельной причиной ошибочного отказа.

Попытка сократить пример по сохранённым векторам до 21+21 не выдержала нового ONNX-инференса: после него score=1. Этот вариант **не считается воспроизведением**. Для координатора сохранён проверенный 37+37, с фиксированными численными параметрами. [Результат неудавшейся редукции](results/selfmatch-reduced/summary.json).

## Отказ всего набора: граница и разумность

Измерено на собственном наборе из 1860 адресуемых JPEG: чистый вариант прошёл полный preflight. После порчи **1**, **19** и **186** файлов каждый запуск дал rc=2 и **ноль новых основных файлов**. [Логи и команды](results/rejection-rate/summary.json), [генератор](scripts/rejection_rate.py).

| Доля испорченного входа | Результат |
|---|---|
| 1 / 1860 = **0.05376344%** | Теряем весь новый комплект |
| 19 / 1860 = 1.02150538% | Теряем весь новый комплект |
| 186 / 1860 = 10% | Теряем весь новый комплект |

В общем случае порог — **один файл, то есть 100/N%**, а не некоторый допустимый процент. Для N=100000 достаточно 0.001%. Старые файлы в уже заполненном out-dir сохраняются, поэтому их существование не доказывает успешность новой попытки; rc необходимо учитывать. Тест сохранения прежнего вывода прошёл, нового протокола публикации не добавлено.

Далее **расчёт при условии независимой вероятности p порчи каждого из 1860 файлов**, не измеренная статистика набора жюри: `P(потерять комплект)=1−(1−p)^1860`.

| Вероятность порчи одного файла p | Вероятность не получить комплект |
|---:|---:|
| 0.001% | 1.8428% |
| 0.01% | 16.9734% |
| 0.1% | 84.4472% |
| 1% | 99.99999924% |

**Оценка правила:** для строгого офлайнового submission это разумный безопасный отказ: пропуск строки ломает соответствие NPY исходному CSV, чёрный/нулевой суррогат выдаёт неисправность за результат модели. Ранняя диагностика лучше прежнего падения после части дорогого инференса. Но толерантность к испорченному набору жюри остаётся **нулевой**; F5 устранил позднюю аварию, а не обеспечил частичный результат. Если организатор допускает повреждённые элементы, координатору нужно согласовать отдельный контракт их обработки. Самовольно менять формат, пропускать кадры или добавлять фиктивные результаты по этому аудиту не предлагается.

## Решение для координатора

**Оставить bce72e7 и 0b8a23d в main.** Их откат не устраняет найденную проблему и возвращает исправленные сбои. При этом **F1 остаётся открытым**: воспроизводимый штатный запрос с точной копией в галерее получает отказ при конечном score. Это приоритетнее косметики и важнее самого факта «111 зелёных тестов». Следующие предметы решения — остаточное вырождение k-reciprocal и четыре пробела тестового покрытия; политика отказа всего набора требует принятого входного контракта. В этом задании выполнена проверка, решения и изменения кода оставлены координатору.
