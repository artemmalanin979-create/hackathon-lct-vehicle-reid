## Что было формальным и что дополнено

1. **Вход в решение.** Старый корневой README был обзором проекта и ссылался на начало большого `SOLUTION.md`; буквального `Readme.md` не было. Теперь таблица ведёт на устойчивые ASCII-якоря нужных разделов; подробный текст хранится только в одном месте.
2. **Одна команда.** В SOLUTION был запуск `--no-build` уже собранного образа после предварительных ручных шагов. В service/README вариант `--build` существовал, но не был собран в единый путь центральной документации. Добавлена команда сборки и старта из корня, с явными условиями. Подготовка Docker и получение данных остаются предпосылками, а не скрытыми действиями команды. Исправлены противоречие о старом `base-images.tar.gz` и безусловное утверждение «офлайн-поставка закрыта полностью».
3. **Порог.** До правки уже были содержательные формула, критерий и tie-break — это не было простым упоминанием числа. Добавлены вывод формулы, объяснение выбора худшего показателя, смысл долей 0.10/0.25/0.40, численный компромисс с максимумом F1. Код `Sweep` включает дополнительную reject-all точку; прежнее описание этого не отражало.
4. **Версии.** Runtime был полным и точным; считать все зависимости отсутствующими было бы неверно. Но применённый в ANN-бенчмарке FAISS отсутствовал, `websocket-client` для съёмки UI не был раскрыт. Известная версия FAISS восстановлена из сохранённого JSON прогона; неизвестные исторические версии названы неизвестными. Снимок Windows не выдан за lock облачной среды или за freeze на дату обучения.
5. **Формат артефактов.** Явно отделены буквальные требования от выбранных свойств реализации: число 10 относится к submission; float32/512/UTF-8/CRLF и отсутствие строки при отказе не полностью регламентированы ТЗ. Уточнено `s >= t` и округление после отсечения.
