# Отчёт job_07 — сквозной прогон и первое честное число

Дата: 2026-09-15. Путь `кадр + bbox → кроп → вектор → поиск → кандидаты → метрика`
работает целиком; все числа ниже получены измерительным контуром
`04-solution/eval/reid_metrics.py` (импортом, без модификаций). Обучения и подбора
качества не было — числа честные, а не красивые.

## 1. Модель и препроцессинг

| | |
|---|---|
| Модель | OSNet-AIN x1.0 (vehicle-reid-0001, Open Model Zoo 2022.1) |
| URL | https://storage.openvinotoolkit.org/repositories/open_model_zoo/public/2022.1/vehicle-reid-0001/osnet_ain_x1_0_vehicle_reid.onnx |
| Размер | 8 836 743 байта (совпал с ожиданием) |
| sha256 | `4aaad3e5db648618b0df3d2ff21c61323985ff9e50194c3d2edd4fb87c92d91f` |
| Лицензия | MIT (карточка OMZ; деривация sovrasov/deep-person-reid, ветка vehicle_reid) |
| Вход/выход | `N×3×208×208` (батч динамический) → `N×512`; сравнение по косинусу |

**Препроцессинг — выяснен по источникам, не угадан:**

- README карточки OMZ vehicle-reid-0001 (тег 2022.1.0): original model ждёт **RGB**
  `1,3,208,208`; конвертированная IR — BGR (нас не касается, у нас сырой ONNX).
- `model.yml`: конверсия в IR делает только `--reverse_input_channels`, **без**
  mean/scale → сырой ONNX не ждёт внешней нормализации.
- `accuracy-check.yml`: на валидации только resize 208×208, use_pillow, BILINEAR.
- Инспекция самого графа (пакет `onnx`): **первый узел — InstanceNormalization на
  входе** — модель сама центрирует/масштабирует каждый канал, поэтому любая
  по-канальная аффинная нормализация на выход не влияет. Подтверждено эмпирически:
  cos(вектор при 0..255, вектор при 0..1) = 1.000000; порядок каналов при этом
  влияет (cos(RGB, BGR) = 0.83–0.96) — оставлен RGB.

Итоговый конвейер: кроп по bbox → PIL RGB → resize (208,208) bilinear →
float32 0..255 → NCHW → ONNX (CPU) → L2-нормировка (накопление в float64).

## 2. Таблица чисел — проверочный сплит (val_query 1110 × val_gallery 750)

Контур возвращает две ветки; **обе приведены** и их нельзя путать:
`полная галерея` — ранжирование всей галереи, `топ-10` — список, усечённый до
K = 10 (столько принимает `submission.csv`; ветка `top_k_then_filter`).

Политика камер везде, кроме отмеченного, — `market` (исключение одноместного
двойника: same id + same camera). Известных запросов 832, отказных 278,
`filtered_queries = 0` во всех прогонах.

вместе с двойником из галереи уходят и трудные одноместные негативы.

### Режим отказа (полная допустимая галерея, presence)

Порог: **t\* = 0.349214** — argmax F1 по PR-кривой самого контура
(refusal_mode=presence, события — top-1 cos каждого запроса) на базовом прогоне
market. Это черновой, но обоснованный порог; калибровка — отдельная волна.

| Прогон | порог | F1 | precision | recall | TNR | AUC-PR |
|---|---:|---:|---:|---:|---:|---:|
| OSNet, market | 0.3492 | 0.8671 | 0.7748 | 0.9844 | 0.1439 | 0.8876 |
| Случайные (порог 0) | 0 | 0.8568 | 0.7495 | 1.0 | 0.0 | 0.7415–0.7541 |

AUC-PR случайных векторов ≈ 0.75 = доле известных запросов (базовый уровень);
подъём до 0.888 — вклад модели. TNR всего 0.144: F1-оптимум при 75% известных
запросов тянет порог вниз, к recall. Если жюри весит TNR отдельно (10% оценки по
ТЗ), порог надо калибровать не по F1 — см. «незакрытое».

## 5. Абляция по номерной пластине — методика и первые числа

По ТЗ §9 остаточные признаки ГРЗ использовать нельзя; разбор данных показал, что
**цвет и позиция пластины переживают размытие**. Точная локализация пластины —
известная трудность (наивный порог садится на панели кузова, EDA §7), поэтому
первый заход — грубые маски: залить нижние 30% кропа серым (127) и/или обесцветить
кроп целиком. Прогон полностью повторяет базовый, меняется только вход; политика
market, полная галерея; порог зафиксирован t\* базового прогона, поэтому
refusal-метрики абляций несопоставимы (распределение косинусов сдвинулось) —
сравниваем ранжирование, оно от порога не зависит.

| Вариант входа | mAP | Δ mAP | Rank-1 | Δ R1 | Rank-5 | mINP | mAP топ-10 |
|---|---:|---:|---:|---:|---:|---:|---:|
| База (без вмешательства) | 0.6566 | — | 0.6310 | — | 0.7873 | 0.6070 | 0.6451 |
| Низ 30% закрыт | 0.5486 | −0.108 | 0.5024 | −0.129 | 0.7236 | 0.4865 | 0.5349 |
| Обесцвечено | 0.5700 | −0.087 | 0.5541 | −0.077 | 0.7260 | 0.5072 | 0.5568 |
| Низ 30% + обесцвечено | 0.4405 | −0.216 | 0.4026 | −0.228 | 0.6142 | 0.3749 | 0.4241 |

**Чтение.** Ни один вариант не падает к случайному уровню (0.01) — решение не
держится на пластине целиком, «хребет» признаков — форма/фактура кузова. Но
просадки заметные. Важная оговорка: полоса 30% много шире пластины (бампер,
колёса, решётка, фары), а обесцвечивание убивает цвет всей машины, не только
пластины — это **верхняя оценка** вклада зоны пластины, а не его измерение.
Методика работает (одинаковый контур, одинаковые метрики, меняется только вход);
чтобы превратить верхнюю оценку в измерение, нужен детектор пластины/мозаики —
следующая волна.

## 6. Что пошло не так и что осталось незакрытым

**Пошло не так:**

1. **Обрыв предыдущей сессии.** Извлечение было запущено фоном, сессия закрылась,
   фон убит — работа середины пропала. В этом прогоне всё выполнено синхронно,
   частями, с фиксацией каждой части в `journal.md`; фоновых задач не было.
2. **Порог не переносится на тест.** t\* = 0.349 (argmax F1 на валидации) на тесте
   отсекает 3 запроса из 1110. Даже на валидации TNR при этом пороге лишь 0.144 —
   F1 при 75% известных запросов почти не наказывает ложные принятия отказных.
   Порог заявлен как черновой; калибровать отдельно (например, по целевому TNR или
   квантилю отказных), и учесть, что доля отказных на тесте неизвестна (наши 25% —
   допущение сплита).
3. **Мелочь журнала:** в записи шага 9 первоначально стояли не те секунды у
   mask30gray (исправлено на 81.5+54.8 с).

**Незакрыто (в порядке важности):**

1. **Калибровка порога отказа** — см. выше; черновой порог в артефактах, механизм
   калибровки — следующая волна.
2. **Честная маска пластины.** Текущие абляции — верхняя оценка; нужен детектор
   пластины (поиск периодической блочной структуры мозаики или лёгкий обученный
   детектор), тогда абляция ответит «сколько метрики даёт именно пластина».
3. **Протокол жюри неизвестен** (из context-split.md): как на закрытом тесте
   исключаются одноместные двойники — неясно; наше число консервативно (если
   протокол жюри мягче, реальные баллы будут выше), но порог, откалиброванный у
   нас, может быть не оптимален там.
4. **mINP в ветке топ-10 не определён** по умолчательной конвенции контура
   (список неполон у 222/832 запросов); в отчёте приведена и ветка
   `zero_if_incomplete`. При сдаче важно оговаривать конвенцию.
5. **Замеры скорости справочные**: на машине жили соседние процессы, разброс
   11.6–20 об/с; финальные замеры организатор делает сам (ТЗ §7).
6. **Претензий к измерительному контуру нет**: случайные векторы легли на
   аналитическое ожидание (0.0099 против 0.0103), вырожденные проверки сплита
   проходили и раньше; параллельный расчёт не встраивался (запрещено брифом).
