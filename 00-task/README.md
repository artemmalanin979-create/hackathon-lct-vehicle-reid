## Название

**Сервис формирования цифрового признака транспортного средства для сопоставления снимков
одного автомобиля из разных локаций без использования государственного знака.**

## Актуальность

В городской инфраструктуре используется большое количество камер и программно-аппаратных
комплексов, фиксирующих транспортные средства в разных локациях, ракурсах и условиях
освещения. Типовая идентификация автомобиля через государственный номер имеет ограничения:
номер может быть нечитабелен из-за ракурса, загрязнения, бликов, перекрытия другим объектом,
низкого качества кадра или отсутствия номерного знака в зоне видимости.

Для задач контроля нарушений, поиска повторных событий и сопоставления данных из разных
источников требуется вспомогательный способ идентификации транспортного средства, который
не зависит от государственного номера.

## Описание задачи

Актуально создание сервиса, формирующего устойчивый цифровой признак автомобиля на основе
визуальных характеристик: типа кузова, марки/модели, цвета, геометрии, видимых особенностей,
повреждений, наклеек, дисков, рейлингов, тонировки и иных отличительных признаков.

Если для части событий по этому признаку ранее был известен государственный номер, сервис
сможет предлагать кандидатов на сопоставление и помогать определить возможного нарушителя
даже при отсутствии читаемого номера на отдельном снимке.

## Формулировка постановщика (анонс в VK)

> **Научи ИИ узнавать автомобиль без госномера**
>
> **Что нужно сделать.** Создать технологию, которая сможет распознавать один и тот же
> автомобиль по его внешним особенностям, даже если государственный номер скрыт или не
> используется. Решение должно формировать **компактный цифровой «слепок» транспортного
> средства, который можно передавать между различными городскими системами** для
> автоматического сопоставления данных с камер.
>
> **Зачем это нужно.** Городские камеры ежедневно фиксируют миллионы событий. Чтобы эта
> информация работала эффективнее, важно быстро понимать, что речь идёт об одном и том же
> автомобиле, независимо от места съёмки. Такое решение поможет повысить точность анализа
> транспортных потоков и станет основой для интеллектуальных сервисов обработки данных.

### 📌 Что из этой формулировки важно и чего нет в карточке задачи

Анонс добавляет **два требования, которых нет в тексте карточки**, и они меняют дизайн решения:

1. **«Компактный цифровой слепок»** — дескриптор ограничен по размеру. Это не «эмбеддинг
   какой получится»: размерность, тип данных и возможная квантизация (float32 → int8 /
   бинарные хеши) становятся проектным решением, а не деталью реализации.
2. **«Можно передавать между различными городскими системами»** — слепок должен быть
   **переносимым артефактом с версионированной схемой**, а не внутренним состоянием нашего
   сервиса. То есть сдаём не только поиск, но и **формат обмена**: сериализация, версия
   модели, при которой слепок получен, и правило сравнения двух слепков на стороне
   потребителя.

Оба пункта стоит заложить в архитектуру сразу — см. [`../03-plan/architecture.md`](../03-plan/architecture.md).
Возвращаться к ним после обучения моделей будет дорого.
